## 结论（对照原先未证明的那件事）

原先说「还没被证明的只有一件事：真实模型会不会一次就写出合法第一段」。

**这一次可以。** Live 模型第一次 `propose_opening_ponds` 就交了两段可通过 `excerpt_job` 的正文（无时间跳、口播、枚举、介绍句、解释接头；书名 2-gram 在段里；前两句起法不同），handler 未拒、未修，直接停选。

同时可以下的判断：

1. **假胜利那张皮这轮交不出来了。** 没有「这本书」槽、没有「后来他明白 / 都市修真，他不修仙」、没有日历梗概、没有老李口播、没有三张互斥轴。卡上是工作书名 + 开头。这不是检测器变绿、简介还在。
2. **思考在执行新题面，不是 4.10 那种躲反例。** `thinking.txt` 在数 60–260、从段里抠书名、核对第一句起法、助手正文留空。方案 P2 删的是负例检查表；正向规格被当成检查表，是换任务之后的预期，不是下一闸的理由。
3. **不要把「两段都有超凡收束」写成未完成的真胜利。** 原稿 §6 把「后视镜多了一个人 / 口袋里多了一枚钥匙」算作**发生**（要保留的工作），上岗当助手才是明白、金句、口播、日历。方案目标态是交得出一场正文、说完交不了卷（P1/P4），不是规定发生必须长成某家停法。§9.2 明确不做 form 轴；P5 说两张的差异在正文里的人/地/事即可，不必再发明「停点类型」。都市修真两段都停在场上的异常，是「跟用户点名的题材」，不是简介换皮。把段末钩子再做成组检查，等于把优化打成店招课。
4. **n=1，题材只有都市修真。** 不能外推「每次都一次过」或「校园/历史同样」。S13 其余记录未跑；不回写阈值。
