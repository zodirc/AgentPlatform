# 0112 · 知识库条目质量治理

对附件 40 条 FAQ 对照 `data/business_context.md` 做体检。检测是确定性规则，一条命令出报告，不依赖大模型是否调用工具。

```bash
python3 eval/0112/scan.py
```

产物：本目录 `findings.json`、`report.md`。

---

## 问题分类定义

从附件数据归纳（过时、互斥、空白、未覆盖），不是套平台术语。

| 类型 | 代码 | 影响 | 建议动作 |
|------|------|------|----------|
| 空条目 | `empty` | 命中后无答案，等于没有这条知识 | 补写或下线 |
| 与现行规则矛盾 | `stale_conflict` | 自动回复念错政策，客诉或资损 | 修改 |
| 同问重复 | `dup_question` | 检索可能打到两条互斥答案 | 合并（留对的，删错的） |
| 库内互斥 | `intra_conflict` | 同一主题口径相反，无法判定以谁为准 | 合并 |
| 覆盖缺口 | `coverage_gap` | 规则有、库没有，只能编或拒答 | 新增 |

---

## 检测方法

1. 解析规则文件里的可核对条款：7 天无理由、运费分担、24 小时发货、合作快递、不支持货到付款、仅电子发票、会员门槛、满减、客服时段。
2. 对每条答案做模式对照（空串、货到付款、30 天无理由、全部商家承担运费、48 小时当默认 SLA、顺丰当主快递、纸质发票、错误满减/叠加、7×24 等）。**不写死 KB 编号。**
3. 问句归一化后合并同问；退货类运费口径聚类打库内互斥。
4. 规则有、语料没有的主题记缺口（邮件客服、电子发票「订单详情页」入口）。
5. 规则没写的内容（价保、海外、支付密码归支付平台）不标过时。

未在热路径再调 LLM。`mock` / 真实 API 对本题不是必须；规则扫描可单独复现。

## 治理建议逻辑

- **P0**（当天）：空条目、退货窗口/运费/货到付款、同问、运费互斥。
- **P1**（本周）：发货时效、快递、发票、会员、优惠券。
- **P2**（排期）：客服时段措辞、邮件缺口。
- 同问且一条已对齐规则：留对的，删/跳转错的。
- 缺口只新增，不把错误条目改成「什么都写」。
