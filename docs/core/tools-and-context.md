## 1. 能力即工具

检索、改稿、exec、委派、验证，以及编码时找定义、看波及、改完再验，都是 **工具**（或焊进既有工具结果），由模型在 AgentEngine 循环内按需调用。  
加能力 = 增强工具的结果契约或 handler，**不改 while、不加固定 pipeline 节点、不新增模型必须学会点的导航工具名**。

| 字段 | 作用 |
|------|------|
| `name` / `description` / `input_schema` | 进请求级 `tools[]`（与 system 文本分离） |
| `side_effect` | 只读 / 写盘 / shell … 决定并行与审批默认 |
| `approval` | 是否打断等待用户 |
| `timeout_s` | 单次调用上限 |
| `handler` | async；可流式打事件 |

约束：

- 工具结果进窗前统一过 **budget**。最近一次读文件可放到约 32k 字，其余超长结果默认约 4k 字头尾截断。  
- 连续只读可并行；写盘 / shell 串行。同 Turn 内：写盘批准一次后同类写盘粘性免再审；**shell 第一次仍要审**，通过后本 Turn 同类 `run_command` 也可粘性。  
- 评测无人值守 Turn 不拦人审。  
- RAG **只**以 `search_sources` 的 `tool_result` 回灌，禁止每轮预注入向量包。  
- 多 agent **只**经 `delegate` 子 Run，摘要回灌。  
- `read_file` 先过已读登记：重复覆盖区间可 skipped；每 Turn 次数有硬帽（默认 16）。
- 写作：`draft_section` / `update_outline` 的返回值带 `visible_chars`（实体文字，不含空白）。用户点名 N 字且不足约定的 85% 时带 `length_short`；成篇默认 5000–6000。章纲过薄（章正文 &lt; 200 实体文字，且用户未要目录）时带 `outline_thin`。`draft_section` 另带 L0 receipts 与 L1 `writing_signals`（`net_signal` / `repair_span`）。弱分同轮 `propose_patch`，不改磁盘公式、不加循环节点。无关旧稿走 `occupy=fresh` 归档，不让用户先删文件。

## 2. Coding（agent 场景）一次用户提问里实际发生什么

模型已经会点 `search_codebase`、`edit_file`、`run_tests`。平台不另发明一套导航工具让它学，而是在这些调用的**返回值里塞进它没法假装没看见的事实**：定义到底在哪、改动能波及谁、交卷前测没测过、issue 里的例子复现了没有。

官方是否判这道 SWE 题通过，看的是 Docker 里跑官方测试（`resolve_rate`），不是看这些探针绿没绿。探针只保证模型在交卷前拿到过验证信号。

### 2.1 从读题到交卷

用户发来一道题（工作区里通常是 `problem.md`）。runtime 先走确定性 Intake（斜杠命令、@路径），再进同一条推理循环：组窗 → 调模型 → 若点了工具就执行并回灌 → 否则尝试结束。

模型应按这个顺序干活（写在 `scenarios/agent/system.md`，平台用返回值和终局拦截落实，不靠再加循环节点）：

1. **读题**：从 issue 抽出符号名、报错串、失败测，不要先 `list_dir(".")` 逛仓库。  
2. **先复现**：用 issue 里的最小片段或失败测跑一遍，看坏现象在不在。改完必须用**同一条命令**再跑。  
3. **找定义**：符号名走 `search_codebase`。它先在工作区符号表里粗筛候选文件/行，再交给语言服务器确认「这就是这个函数的定义」。确认过的才进 `definitions[]`；词面搜到的命中不得冒充定义已找到。模型如果直接 `grep` 一个符号名，handler 会整条改去这条路径，避免它靠全文检索当导航。模块名、形参这类本来就不是定义，查空是结构边界，不是索引没建好。  
4. **打开定义再改**：`read_file` 命中处。文件太长被截断时，结果里带标题/符号大纲，让它跳段而不是从第一行盲翻。Markdown/纯文本同样抽标题。  
5. **就地改**：`edit_file` 换一小段。成功时结果里带两块平台算的东西——这段大概影响哪些引用（方便决定还要不要查调用方），以及这次写入的语法/诊断（新引入的问题列在 `new_issues`）。另外附上「跟这个文件最像的测试文件 + 一条可复制的 pytest 命令」。平台**不代跑**这些测试，只把命令放到模型眼前。  
6. **改完再验**：先看自己引入的诊断，再跑相关测试命令，再 `read_lints` 看邻文件，最后用第 2 步那条复现命令再跑一次。测试输出会从**未截断的全文**里抽出失败第一条（模型常写 `pytest | tail`，页脚被管道吃掉时旧逻辑会静默没有摘要）。  
7. **想收工时**：若模型不再点工具、直接输出终稿，平台检查两件事。第一件：成功改过代码之后有没有跑过测试类命令。第二件：仓库测试绿了之后，issue 正文里出现过的例子有没有在**最新一次编辑之后**被成功命令覆盖——代码块、引用命令、REPL、输入输出样例都算；issue 里的失败签名如果还在输出里，不算覆盖；表/ASCII 一类「按某种 format 写出再读回」必须用同一套参数走一遍写再读；issue 明确说大小写不敏感时，还要用折叠大小写后的变体再练。这些例子只从 `problem.md` / `PROBLEM.md` / `issue.md` 抽，**不得把官方隐藏测试泄漏给模型**。任一缺口就往对话里塞一条用户口吻的提醒（不是工具结果，菜单里也没有这个工具），然后**再进一轮**组窗/调模型。每类提醒每轮提问最多一次；剩下步数不够（默认还要留 10 步）就省略，避免卡在死循环。取消或已经失败的 Turn 不拦。审批挂起再续跑时，这两类「还欠什么」必须能从 checkpoint 恢复，否则会把行为门弄丢。

产品对话**不等**符号表建完再受理，避免用户干等。只有官方编码评测套件会在开题前等索引 ready，免得第一下查找撞上空表。

语言服务器是定义和引用的权威；工作区符号表只是粗筛，没有向量、也不给写作/情报检索用。界面上的进度条只报告「扫到哪了」，ready 之前不得画成已经能精确定位。

### 2.2 模型爱走的捷径，handler 直接改道

不靠提示词劝。模型仍点原来的工具名，执行层改走该走的路：

- 用 `cat` / `head` / `tail` / `sed -n` / `nl` **只读一个文件、没有管道和写盘** → 内部改成 `read_file`，这样走大纲、已读登记和组窗折叠，而不是把整文件打进 shell 事件。带管道、通配或重定向的命令原样进壳，平台不猜。  
- `grep` 一个很像符号的词 → 整条进上面的找定义路径。  
- `update_plan` 清单内容和上次完全一样 → 告诉它没变，不再刷一条工具完成事件（计划刷新曾经能占掉一成多工具事件）。  
- 同一文件已经完整读过，再读同一覆盖区间 → 拒绝，逼它去改而不是反复翻。组窗把旧读折叠掉之后，允许再读一次被挤掉的文件。

### 2.3 评测题的测试不在这棵源码树上跑

SWE-bench 每道题有一张官方 Docker 镜像，里面才是该题的解释器和测试环境。工作区只是 checkout 出来的源码。模型若在源码树上 `pip install` 或 `pytest | tail`，测的不是评委用的环境，还可能把失败摘要截没。

因此：仅当这次提问带评测标记、工作区里有实例标记文件时——

- 测试命令（即便后面跟着 `| tail` 这类只为好看的管道）剥掉展示用管道，把**完整输出**丢进那张镜像的 `/testbed` 里跑；  
- `python -c` / `python --version` 这类「环境里有没有这个包」的探测同样进镜像；  
- 禁止在裸源码树上 `pip` / `uv install`；  
- 同一道题多次跑测时复用容器，只把改过的文件按修改时间和大小增量同步进去，少付冷启动墙钟；镜像里断网；  
- 镜像不在或看板冒烟没过 → 硬失败并写明原因，不得当成「模型得了 0 分」。

日常用户在产品工作台里提问**不走**这条路径。`make ops-swe-eval-ready` 做的是：给 api/runtime 挂上 docker.sock、预拉镜像、对每张镜像跑 python/pytest 冒烟，看板显示就绪之后才能信官方通过率。

写作和情报场景继续用资料检索，不打开编码用的查找/改文件结构能力；编码场景反过来，不用资料检索来找代码位置。

## 3. 请求通道怎么拼

| 通道 | 内容 | 注意 |
|------|------|------|
| System | 场景 `system` 提示 | 跨 step 求字节稳定；**不焊**工具 schema / 大纲全文 |
| Tools | `tools[]` how-to + schema | 与 system 文本分离 |
| Rules | 作品规矩 / 大纲摘要等 ≈2k | 不焊进 system |
| Writing / Runtime / Session | 焦点、计划相位、步进注入 | Runtime 宜在 Conversation 之后；Plan 文案走易变垫，**不焊**进 system |
| Conversation | user / assistant / tool_results / compact | **卫生与 80/90/95 主要作用于此** |

物化顺序：**稳定前缀 → 历史 → 易变垫底**；`tools[]` 不进 message 串。

## 4. ContextEngine 逐步经过

每次准备调模型前跑组窗，只改 **本步** 模型窗。指纹未变且无待做摘要时可复用，避免同消息反复压。

### 4.1 卫生（几乎每步，不看 fill）

| 步骤 | 做什么 |
|------|--------|
| **budget** | 单条超长 `tool_result` **头尾各半**截断，留再读指针。默认约 4k 字；**最近一次成功读文件**可放到约 32k，避免刚读完就被折没 |
| **read_fold** | 同一 path 的旧 `read_file` 留首尾约 300 字符 + 行号范围，只保留最近一次全文 |
| **microcompact** | 历史里成串已完成旧 tool 结果折成短占位；**不拆**当前这次配对 |

微折叠是卫生，**不是**超限压缩。pager 已在工具层转成读文件时，组窗按读结果折叠，不按 shell 原文再折一遍。

### 4.2 填充率与阶梯

```text
fill ≈ 本窗估计 token / (context_window − output_reserve)
```

默认窗 **128k**、输出预留约 **30k**（随窗按比例缩放）。fill 是相对这个分母，不是相对原始历史长度。

| 阈值 | 动作 | 损失形态 |
|------|------|----------|
| ≥ **0.80** | **collapse** | 留头 + 热尾（热区约 0.35）；中间折叠成占位 |
| ≥ **0.90** | **snip** | 从最旧开始删完整消息组（user–assistant–tool），直到低于阈值 |
| ≥ **0.95** | **autocompact** | 整窗 → 结构化摘要（默认定增量，不在首 token 前同步再唤一次模型） |

阶梯由低到高，低档不够再升档。摘要是最后一档，不是每轮税。只改本步模型窗；磁盘稿与 Web 聊天记录通常仍完整。  
Turn 结束后若 fill 偏高：可异步刷新会话摘要缓存，**不挡**下轮首 token（R2）。

## 5. exec 沙箱（与审批正交）

自动选择一次后粘滞进程寿命：**Landlock（优先）→ bwrap → off**。`off` 仍约束路径不得爬出当前 Work 根，并叠容器边界，不是完全裸奔。强制变量仅作运维逃生。

```text
审批已过（或本工具免审 / 评测无人值守）
  → run_command / run_tests
  → 这次是官方编码评测题？
       ├─ 是：剥 |tail → 在该题 Docker 镜像里跑完整测试；环境探测同样进镜像
       │     拒 pip/uv install；容器复用 + 增量 sync（/testbed，--network none）
       └─ 否：Landlock（优先）→ 否则 bwrap → 再否则 off + 软路径 jail
            编码评测禁网时强制 bwrap --unshare-net；没有 bwrap 则硬失败
```

| 项 | 做法 |
|----|------|
| RO bind | 必要系统树 |
| RW bind | 工作区 → `/work`（必要时再绑一份真实绝对路径，避免工具认绝对路径） |
| tmpfs | `/tmp`；也遮住无关的产品根，防串 Work |
| 网络 | **默认不断网**（护宿主 ≠ 禁 curl）。编码评测禁网时强制 bwrap 断网；没有 bwrap 则硬失败，不漏出 |

| 门 | 问题 | 失败形态 |
|----|------|----------|
| **审批** | 这次允不允许跑 | `waiting_approval` / 拒绝原因写进 tool_result |
| **沙箱** | 跑起来能碰哪 | EACCES / 可观测降级 |

不在热路径上再套一层 LLM 安全裁判。Plan `executing` 只预授权清单内写盘，**不等于** shell 免审。
