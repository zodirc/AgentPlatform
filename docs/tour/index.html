原则与速率红线

扩能力 = 焊进工具结果或旁路索引；不改 while、不新增模型必须学会的工具名。三线 uplift 全部落在索引期 / 组装期 / 结果契约。

#原则验收含义
R1不挡受理turn.accepted / TTFB 不因新逻辑同步恶化
R2首 token 前不加同步模型禁止热路径同步摘要 / 裁判 / 改写
R3热路径 CPU 毫秒级整库 embed、大扫描不上主链
R4重活异步索引、审计、软预压缩走旁路
R5可测才合并make gate / Ops suite 证明

硬约束 + 明确不做（近两日钉死）

  • 服务间无 Python 互 import；事实桥 = Postgres LISTEN/NOTIFY。
  • Engine 禁止 if scenario ==（constitution-check）。
  • Cancel ≠ failed；审批恢复同 run_id；审批门 ⊥ 沙箱门。
  • 不做 CST / call-graph / 全仓 LSP indexing；不做给 agent 挂 search_sources（场景隔离）。
  • 不做 smoke 升 SCORECARD；harness 无 resolve → suite failed（不得粉饰 completed）。
  • 编码结论：模型几乎总能碰到该改的文件，查找调用占比极低 → 官方通过率的瓶颈不在符号表/语言服务器，而在改对没有、验没验过。

领域对象与 Turn 状态机

Principal → Work（work_id, work_root）
              └── Session*（transcript / 策略 / compact 摘要）
                    └── Turn（一次用户闭环）
                          ↔ Run 1:1（checkpoint · cancel · lease）
                               └── Step*（仅事件粒度）
对象含义关键约束
Work稿件与资料世界根不随 Session compact 拆散
Session连续性容器换 Session 不换默认 Work
Turn受理到终态恰好一个 Run
Runagentic loop 实例审批挂起仍同 run_id
 
pending → running ⇄ waiting_approval
               ↓
        completed | failed | cancelled
  • failed(start_timeout)：无人领取超时
  • failed(runner_lost)：租约丢失无法安全续跑
  • 取消后继续聊 = 同 Session 新 Turn

请求主路径（端到端）

  1. Web POST 会话 turn → api 鉴权 / 准入
  2. 同一事务 INSERT turns + runs；pull 可领则 NOTIFY
  3. 客户端先得 202；业务首事件 turn.accepted 在 runtime claim 后发出
  4. runtime：lease 心跳 → Profile → ToolScope → Intake → Engine
  5. 关键节点 append-only turn_events → pg_notify
  6. api LISTEN → SSE 回放 + UPSERT turn_views
  7. Web 只消费事件流与投影；不推断阶段
易混点：api「尽快」只做落库 + 分发；TTFB 看 turn.accepted 经 SSE 到达时刻。

StartTurn / 控制命令

api 尽快只做落库和分发通知，不把任务推到 runtime。runtime 有空位才领，领了之后心跳续约。客户端先拿到 202；业务上「这题开始了」要等 runtime 发出 turn.accepted。

超过领取时限仍无人领 → failed(start_timeout)；租约丢失且无法安全续跑 → failed(runner_lost)。回退模式才是 api HTTP 调 runtime 的 start-turn，传输失败则客户端 502。

同族控制命令

取消 / 审批 / patch 等默认经 run_commands + NOTIFY，由当前持有租约的 runtime 副本消费（HTTP 内部命令可作兼容回退）。

官方评测无人值守

这次提问带评测标记时，StartTurn 即预批准写盘和 exec，不拦人审。字段随 checkpoint 存活。

旁路预热

Profile 打开结构预热且设置允许时，StartTurn 上后台预热符号表，不 await——不挡 turn.accepted / 首 token。

两层结构

TurnController（不进 while）
  · runtime 自己领取（默认）或 api HTTP 推送 start-turn（回退）
  · runner 租约心跳；丢失可回收
  · ScenarioRegistry.get → Profile → ToolScope
  · Intake：InputCompiler（slash、@path、附件）
  · shouldQuery：纯本地命令可零模型结束
  · 发 turn.accepted → Engine；收尾写终态

AgentEngine while step_count < max_steps:
  1. ContextEngine.assemble（卫生 + 80/90/95）
  2. ModelGateway.stream（可 abort；网关 Cancel ~50ms；工具流内 ~250ms）
  3. 解析 text · thinking · tool_use
  4. 有 tool → 审批？→ 执行 → tool_result
     · 更新「还欠测试 / 还欠 issue 例子」；官方编码评测可把测改去该题 Docker
     · checkpoint → continue
  5. 无 tool → 若想收工却还欠验证：
     · 塞一条用户口吻提醒 + tool.completed(verify_receipt=true)
     · continue（再进一轮，不是合成 tool_result）
     · 否则 final 退出
  6. 每步 finally：checkpoint
  • Controller 管 Turn 前后；Engine 管推理循环，不感知 scenario 名字。
  • Guard（取消 / 分层超时 / Stall Watchdog）旁挂全程，不是 while 新节点。
  • agent Profile max_steps: 150；writing 为 40。

AgentEngine 单循环（权威图）

加能力 = 工具或焊点；不改 while。模型网关：仅在未吐 token 前重试；首字节快超时 + step/model/tool 分层超时。

Intake（确定性，非意图分类）

用户输入 → InputCompiler → shouldQuery
  ├─ 否：本地响应（/help、部分 /compact）+ completed
  └─ 是：进 Engine；首轮由模型决定直答或 tool_use

scenario_id 由 API/会话指定，不由 LLM 猜测。

审批 · 取消 · 恢复

  1. 需审 → approval.requested → waiting_approval，同 run_id checkpoint（含「还欠测试 / 还欠 issue 例子」）
  2. Approve → 同 run_id 续跑；Deny → 拒绝 tool_result（含原因）
  3. 官方评测无人值守：StartTurn 即预批准写盘/exec，门控工具自动过审；字段随 checkpoint 恢复
  4. 写盘粘性：人工批准一次写类工具后，同类写免再审
  5. Shell 粘性：人工批准一次 run_command 后，本 Turn 后续同类 shell 免审（≠「Shell 永远逐步审」）
  6. Plan phase=executing：清单内写盘可按计划免审；普通 update_plan 进度 ≠ 已批准开工
  7. 审批门 ⊥ 沙箱门；官方编码评测下 run_command/run_tests 可改去该题 Docker 镜像（剥管道、拒 pip、容器复用）
取消含义
软 cancel_requested协作式停下
硬 cancel_force可杀流 / 子进程
终态 cancelled（≠ failed）；继续对话 = 新 Turn。Cancel 须打断 backoff 与 provider HTTP 流（网关流 ~50ms；工具输出流内检查 ~250ms）。

TurnState（审批挂起后必须还能接着验）

执行态 dataclass，经 checkpoint 序列化。审批中断后再续跑，不能把「还欠测试 / 还欠 issue 例子」弄丢。

编码 Turn：找定义、看波及、改完再验

模型已经会点 search_codebase、edit_file、run_tests。平台不另发明导航工具，而是在返回值里塞进它没法假装没看见的事实。官方是否判这道 SWE 题通过，看 Docker 里跑官方测试，不是看这些探针绿没绿。归因也钉死：模型几乎总能碰到该改的文件，查找调用占比极低——瓶颈在改对没有、验没验过，不是符号表没建好。

找定义。符号名走 search_codebase（直接 grep 符号名会被整条改过来）。先在工作区符号表里粗筛候选文件/行，再交给语言服务器确认「这就是这个函数的定义」。确认过的才算找到；词面命中不得冒充。模块名、形参本来就不是定义，查空是结构边界，不是索引没建好。

看波及。edit_file 成功时结果里带这段大概影响哪些引用；精查仍可用 find_references。

改完再验。写入时做语法门和增量诊断；附上相关测试文件和一条可复制命令（平台不代跑）；测试从未截断全文抽出失败第一条（| tail 丢页脚也不丢摘要）；issue 正文里的例子必须在最新编辑后再跑过；模型想收工却还欠验证时，平台塞一条用户口吻提醒再跑一轮。

  • agent 有结构工具、无资料检索；writing / intel 相反。
  • 明确不做：CST、call-graph、把引用索引进符号表、全仓语言服务器 indexing。

想收工却还欠验证时再催一轮

模型不再点工具、直接输出终稿时，平台检查两件事，缺哪条就往对话里塞一条用户口吻的提醒（菜单里点不到这个工具，对话记录里也不是 tool_result），落一条 tool.completed（verify_receipt=true），然后 continue 再进一轮。不挡取消/失败；每类每 Turn 至多一次；剩下步数不够（默认还要留 10 步）则省略。

第一类：成功改过代码之后还没跑过测试类命令。提醒里会引用已经给过的相关测试命令，以及最近一次测试失败首条（如果有）。

第二类：仓库测试已经绿了，但 problem.md 里写过的例子还没在最新一次编辑之后被成功命令覆盖。

审批挂起后再续跑，这两类「还欠什么」必须能从 checkpoint 恢复。第5轮：这条提醒发出率 0.80（第4轮曾掉到 0.20）；发出后真去跑测试的只有 0.25——催了仍常不跟测。

绿测不够：issue 里的例子改完后还得再跑过

平台从 problem.md / PROBLEM.md / issue.md 抽出 issue 正文里出现过的例子。只复现 issue 写过的东西，不得把官方隐藏测试泄漏给模型。仓库测试绿了仍不够：这些例子必须在最新一次代码编辑之后被成功命令覆盖。

优先抽代码块、引用命令、REPL、输入输出样例。issue 里的失败签名如果还在输出里，不算覆盖。表/ASCII 一类「按某种 format 写出再读回」必须用同一套参数走一遍写再读。issue 明确说大小写不敏感时，还要用折叠大小写后的变体再练。

第5轮对照：14182 转绿，补丁同时改了写路径（header_rows）和读侧（data.start_line），与写再读义务同向，仍最慢（约 30 分钟，镜像跑测和复现占主导）。14365 回落，补丁只加了 re.IGNORECASE；issue 样例里没有小写 NO，大小写折叠这一门没能逼出官方隐藏的 roundtrip 测。
