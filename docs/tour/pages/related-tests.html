失败摘要、相关测试命令、找定义路径

失败摘要、相关测试命令和 Locate 定义都写进既有的 tool_result，不另开工具名。附带的测试命令默认留给模型决定要不要跑。产品编码回合里，模型已经准备结束、测试仍欠着时，引擎执行其中路径最长的一条，把输出放回对话。评测回合不执行这一条，分数只来自镜像里的 harness。

  • ◆ 要点 相关测试是 tool_result 里的事实。产品回合在交卷前执行一条；评测分数不看这一条。

三条车道

失败摘要（test_summary）
  旧逻辑要求 pytest 尾行；模型常写 | tail，或 32k 截断丢掉页脚 → 摘要静默缺失
  现行从未截断全文旁路解析，兼容 -q / unittest / ERRORS
  first_failures 写入工具结果；落入 TurnState 时再截 400 字，供 verify receipt 引用
  is_testish_command 决定这次 run_command/run_tests 能不能清掉 verify_pending
  冒烟从 0 走到第5轮 0.50，出口线仍 ≥0.6（评测观察）

相关测试（edit_file 成功后附带）
  最多 5 条：{path, command}，command = python -m pytest {path} -x -q
  产品交卷且 verify_pending：run_product_verify_hook 执行路径最长的一条，每 Turn 一次，然后 continue
  模型能在同一次回合里看到输出。评测或 product_post_edit_hook 关闭时不执行
  评测若在工作区里跑这条命令，结果会看起来像分数，而官方分在镜像里
  命名启发式 rglob 预算 250ms；import 反向最多 250 文件 / 400ms
  跳过 .git / venv / node_modules / __pycache__ / build / dist …
  优先精确到单个测试文件（便于送进该题 Docker），而不是 pytest 全库
  第5轮：coverage 1.0，adoption 0.0——门能给出命令，模型仍经常不跑
  ◆ 要点  相关测试是 tool_result 里的事实。产品回合在交卷前只执行一条。评测分数仍只认镜像里的 harness。

找定义（search_codebase / Locate）
  符号表粗筛 top_k=5 → LSP 在标识符列确认 → 只有确认过的进 definitions[]
  确认失败：locate_incomplete=true，词面 hits 不得冒充定义
  模块名 / 形参查空是结构边界，不计索引故障
  grep 符号形 pattern 整条改道至此（redirected_from=grep）
  产品对话不等 AST ready；仅评测套件开题前等待
  索引：默认 workspace_ast_inline=False，入队 work_ast_index_jobs；脏文件 debounce 0.5s、积压帽 500
  第5轮融合成功率 0.625（n=8）；查找仍不是官方通过率的主因
  ◆ 要点  符号表无向量。写作/情报走 search_sources，打开 Locate 只会把散文专名当代码符号。
