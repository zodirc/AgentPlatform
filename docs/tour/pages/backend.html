后端：时序、并发与负载

控制面与事件面反向。浏览器不直连 runtime。Postgres 是跨进程唯一实时总线。默认 TURN_DISPATCH=pull。机制写在各 ASCII 步骤旁；页底 PNG 只是同一条主链的海报。

  • ◆ 要点 设计取舍：漏了会用错模型（当队列、当失败、当第二台库、当线程）

微观时序

同一 Turn。t1 与 t3 在浏览器侧几乎同时发生；t2 与浏览器无 TCP。
三道闸互不替代：门口丢掉请求 · 执行面停止领取 · 观看者占用的是另一类资源。

t0  登录（一次性）
    Browser  POST /api/v1/auth/login
         │   Cookie 尚未存在；body = 用户名/密码
         ▼
    Caddy  handle /api/*  → reverse_proxy api:8000
         │   角色：L7 reverse proxy + 路径分流（/api,/health → api；其余 → web）
         │   不做：Cookie/HMAC 鉴权、缓冲业务体、sticky session、持有 Turn 状态
         ▼
    api    校验密码 → HMAC-SHA256 签发会话 token（非 JWT）
           Set-Cookie: agent_end_user=…; HttpOnly; SameSite=Lax; Path=/
           TTL 30d；payload.sub=user_id，pv=密码版本（改密即整站失效）
           无独立 CSRF token：依赖同源 + SameSite；无 FastAPI CORS
           （页面与 /api 同 host，由 Caddy 拼成同源）

t1  发送（命令面，短连接）
    Browser  fetch POST /api/v1/sessions/{sid}/turns
             credentials: include  → 自动带 Cookie
             body JSON { message, client_request_id, scenario_id? }
         │
         ▼
    Caddy  透传；HTTP/1.1 短请求，无流式语义
         │
         ▼
    api    RequestContextMiddleware  分配/回写 X-Request-ID
           require_session_actor
             Cookie | Bearer → HMAC verify → EndUser.active
             失败 401；admin Basic + bypass → 映射 system user（评测/遗留）
           assert_session_owner(sid, actor)     非 owner → 403
           check_dispatch_admission(owner)
             全局 unclaimed < 32 且 本用户 unclaimed < 2
             否则 429 + Retry-After:5   ← Turn 尚未 INSERT
           同一事务:
             INSERT turns(pending) + runs(accepted, pull_eligible)
                    + turn_views seed
             pg_notify('turn_dispatch_channel', run_id::text)
           响应 202  { turn_id, run_id, status: pending }
           （幂等命中 client_request_id → 200，不新建）
    ◆ 要点  队列满是 HTTP 429，Turn 还没 INSERT。写成 failed，终态语义就脏了。

t2  领取（执行面；与浏览器无 TCP）
    runtime  LISTEN turn_dispatch_channel | poll 2s
             _active_turns < 16 ? claim : 不领
             UPDATE runs SET running, lease_expires_at = now()+180s
               WHERE status='accepted'
             INSERT turn_events type=turn.accepted  sequence=1
             触发器 pg_notify('turn_events_channel', turn_id::text)
    ◆ 要点  CAS 失败者 = 已被抢走，勿当回滚重试，否则双 runtime 跑同一 Turn。
    ◆ 要点  编码一步常 60–160s，租约 180s 必须盖过它。更短 → 误标 runner_lost。
    闸② inflight = 本进程 _active_turns（含 waiting_approval），默认 16
      满则停止 claim，压力留在未领取队列，回头顶到门口 429。
    lease 心跳 10s。过期且不能安全续跑 → failed(runner_lost)。
      审批挂起仍占同一 run_id：续跑必须是同一执行实例。
    claim 超时 15s 无人领取 → 已 202 的请求随后 SSE failed(start_timeout)
    内存 从此吃 runtime 4g（组窗、模型流、工具结果）

t3  订阅（SSE 面，长连接）——通常与 t1 的 202 之后立刻发起
    Browser  GET /api/v1/turns/{tid}/stream?since_sequence=0
             Accept: text/event-stream
             Cookie 再次带上（SSE 是另一条 HTTP，必须重新鉴权）
         │
         ▼
    Caddy  同一条 reverse_proxy。SSE = 永不结束的 HTTP 响应。
           Caddyfile 未开额外 buffering；流式依赖：
             · 上游 Transfer-Encoding: chunked / 逐步 yield
             · api 头 Cache-Control: no-cache
             · X-Accel-Buffering: no
               （防 nginx 类代理攒包；Caddy reverse_proxy 默认不按
                nginx proxy_buffering 攒，此头是防御性兼容）
           Caddy 不解析 SSE 帧，不扇出，不存 sequence。
         │
         ▼
    api    require_session_actor     同 t1
           _require_turn_access      get_turn + assert_session_owner
           Last-Event-ID 与 since_sequence 取 max → 续传游标
           StreamingResponse(generator)
             协程: wait(NOTIFY | 2s poll)
                   SELECT * FROM turn_events WHERE sequence > cursor
                   yield "id: {seq}\nevent: message\ndata: {envelope}\n\n"
                   空闲约 14s yield ": ping\n\n"
             单进程一条 asyncio 循环：generator 多数时间 await 让出，偶尔 yield 一帧。
             见到 turn.completed|failed|cancelled
               或 approval.requested → 等投影追上 → 结束 generator
               （暂停点关流，逼客户端 GET /view 再画审批 UI）
    ◆ 要点  挂看是 asyncio Task，不是 OS 线程，也不是一路推理。关页不杀 Turn。
    ◆ 要点  事实是 SELECT sequence>cursor。门铃只唤醒；2s poll 是丢通知的兜底。

    SSE = api 读模型的单向出口（text/event-stream；fetch+ReadableStream 带 Cookie）
      · 载荷 = envelope JSON；游标 = sequence；重连可重放
      · approval.requested 为暂停点：关流，逼客户端 GET /view
      ~14s : ping；45s 无字节视为闷流，带 since_sequence 重连（≤8）
    闸③ SSE 连接数 = 正在看的浏览器数，与 inflight 解耦。
      大量挂起的 SSE 先挤 api 的 fd / 协程 / 1g。

鉴权切面

每条 HTTP 都做，含 SSE GET。不能订阅他人的 turn_id。

        │
        ▼
require_session_actor  → EndUser
        │
        ├─ POST /sessions/{sid}/turns  → assert_session_owner(sid)
        └─ GET  /turns/{tid}/stream    → turn.session_id → 同一 owner 检查

叠回时序
────────
t1 POST        短连接 · api 热池借 1 · 一事务 · COMMIT 后 NOTIFY
               内存：请求 JSON KB 级
               并发：admission COUNT unclaimed（INSERT 之前，避免先写再 429）

t2 claim       runtime 热池 1 · CAS UPDATE · inflight += 1
               加载 transcript → TurnState（此时组窗尚未到 128k）

t3 SSE         长连接 1 / 观看者
               不借热池挂起：LISTEN 独立连接 + 唤醒后短 SELECT
               内存：当前页 envelope（delta ≤8KiB/事件）
               并发：N 路 SSE ≈ N 个 asyncio Task on api 1g
               与 inflight 解耦

t4 assemble    纯 CPU/内存 · 不写库
               峰值 = 组窗对象图（约 5～30 MiB / 满窗 Turn）
               fill≥0.80 才 collapse

t4 INSERT      热池；同 Turn 串行拿 pg_advisory_xact_lock
               按 Turn 哈希的事务级锁：同 Turn 串行拿号，异 Turn 不互相堵
               不是锁整张 turn_events
               16 Turn 并行 ⇒ 最多 5 个真正在 COMMIT
               其余 await Pool.acquire()；排队 >5s → statement/command timeout

t4 模型流      长连接 ④ · 内存在 runtime（不经 PG、不经 SSE 全量）
               SSE 只搬 payload.delta

────────
t1 POST /turns          HOT     短事务 INSERT + NOTIFY
t2 claim                HOT     CAS UPDATE
t3 SSE SELECT           HOT     sequence > cursor（被 LISTEN 叫醒）
t4 INSERT turn_events   HOT     advisory lock + 批写

◆ 要点  bypass 不是第二台库，也不是 RAG 池。LISTEN 不能占热槽。硬删会话要显式清 turn_events。

HOT     checkout 必须快还；慢 SQL 占槽 → claim / 事件批写 / SSE 回放排队
BYPASS  同实例另一组 5 槽、120s，给会超过 5s 的慢 SQL（AST / 硬删 / retention）
LISTEN  checkout 就一直占着；放进热池 = 永久少槽 → extra connect
RAG     psycopg 自建连，第三条绕开 hot 的路径

组窗内存

组窗（每 Turn，不是每 Session）
  ContextEngine.assemble 的 Turn 级 RAM，不是 Session 常驻 128k。
  session_transcripts 落盘前已确定性裁剪。
──────────────────────────────
  CompactionPolicy
    model_window      128_000 tok     模型上下文上限
    output_reserve     30_000 tok     预留给 completion（不计入 fill 分子）
    usable             98_000 tok     fill = assembled / usable
    collapse / snip / autocompact     0.80 / 0.90 / 0.95
    hot_zone           0.35           collapse 时保留的尾部占比
    tool_result        4_000 字       普通 tool_result 头尾截断
    latest read_file  32_000 字       最近一次成功读文件放宽

  驻留位置（同一 Turn 内会有多份拷贝）
    TurnState.messages          真源（工具回灌后）
    ContextEngine.assemble      本步送模型的窗口
    checkpoint (JSONB)          审批挂起 / 续跑
    session_transcripts         Session 级落盘；写入前确定性裁剪，不调 LLM
    模型 HTTP body              序列化后再占一份

  内存数量级（Python 对象图；仓库无 per-Turn RSS 探针，只作规划）
    满 usable≈98k tok → 典型 5～30 MiB / Turn（对象头 + 多份拷贝）
    16 inflight × 20 MiB ≈ 0.3 GiB   仅消息图
    + sentence-transformers 常驻
        gte-small@384     ~0.1 GiB
        bge-m3@1024       ~1.5–2.5 GiB（故 GPU overlay 把 runtime 抬到 12g）
    ⇒ 4g cgroup 下 16 路满窗会先 OOM。
◆ 要点  128k 是这一 Turn 的组窗，不是 Session 常驻。软件帽 16 ≠ 物理可跑 16。

规划上界

软件帽先于 cgroup；热连接先于软件帽。
可回归的最高并发需要 rss_bytes/inflight 与 pool_acquire_wait_seconds；仓库只保证软件帽与 cgroup。
◆ 要点  不要宣称「支持 16 用户同时满负荷编码」。满窗大约 2～4 路。

  维度            默认单副本     备注
  软件执行中      16             RUNTIME_MAX_INFLIGHT_TURNS
  DB 热连接       runtime 5 + api 5    先于 16 饱和
  满窗推理        2～4           4g + 组窗拷贝 + embed
  轻量对话        6～8           窗远小于 98k
  SSE 挂看        数十           api 1g / fd；≠ 能推理 16
  未领取排队      32 / 用户 2    再高 429
  HA 双 runtime   软件 32        近双份 4g；PG 连接再 +12

扩容
────
  make up-ha → runtime-a / runtime-b，共用同一 Postgres 与 agent_data
  claim 走数据库 CAS，不配置 RUNTIME_URL_MAP
  单进程 uvicorn，勿设 --workers（会复制互不相认的 inflight / LISTEN）
  dispatch_wait_seconds / dispatch_queue_depth 顶满再加 runtime
  event_pipeline_lag_seconds / TTFB 变差先查热池与事件批窗（~40ms）

事务与边界
──────────
  create_turn 单事务多 INSERT；NOTIFY 在 COMMIT 后投递
  事件行在 pg_advisory_xact_lock(turn_id) 下分配 sequence
    同 Turn 串行拿号；异 Turn 不互相堵；不是锁整张事件表
  SQL 均 $n 参数化；asyncpg 每连接 statement cache（默认 100）
  加密停在边界：:80 明文，:443 tls internal
  容器内 PG/HTTP 默认无 sslmode=require
  Cookie = HMAC 签名（完整性，payload 非加密）；供应商 Key 静态 Fernet
