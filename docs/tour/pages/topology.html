部署拓扑

浏览器只访问产品面 http://localhost/。Caddy 把 / 交给 web，把 /api/* 与 /health/* 交给 api :8000。runtime 不对浏览器开 SSE。默认 TURN_DISPATCH=pull。执行侧拆成编排 runtime 与平面容器（compose planes.yml：redis / sources-retrieval / model-gateway / sandbox）。并发数字与双池见上一页「时序 · 并发 · 负载」。

  • ◆ 要点 设计取舍：漏了会用错模型

谁在链上

Browser  ──HTTPS──►  Caddy :80/:443
                       │  L7 reverse proxy；无业务状态
                       ├─ /api/*  /health/*  → api:8000
                       └─ 其余               → web
                            │
                            ▼
                     api    鉴权 · 准入 · 落库 · PUBLISH turn.dispatch · 订 live · SSE · 投影
                            不跑 Agent loop；可 enqueue Redis Streams（索引同步）
                            │  COMMIT 后 PUBLISH turn.dispatch(run_id)
                            ▼
                     PG     跨服务业务真源（runs / 耐久 events / CAS）
                     redis  turn.dispatch 门铃 · turn.live.* 活流 · agent.jobs
                            │  SUBSCRIBE / claim CAS（+ poll）
                            ▼
                     runtime :8001（orchestrator · 不公网）
                            领取 · lease · Intake · Engine · 写耐久 turn_events
                            PUBLISH turn.live；EMBEDDING_BACKEND=remote
                            不对浏览器开 SSE

执行平面（同栈 · HTTP 热路径 · 不经 agent.jobs）
────
  redis                 Pub/Sub 门铃/活流 + Streams 异步索引
  sources-retrieval     唯一 embedding 池 · sync/watch · POST /internal/embed
  model-gateway         live LLM NDJSON · POST /internal/v1/complete
  sandbox               bwrap/landlock exec · POST /internal/sandbox/exec
                        （镜像 FROM runtime:slim，无 ST/torch）

旁路（不在用户提问主链）
────
  ast-indexer   后台 AST；SKIP LOCKED 领解析任务；cgroup 768m / 1 CPU
  bench         官方评测 worker；隔离库；不进日常提问路径
  发布台 :9090  同仓旁路控制台；对比指纹、标 dirty、分模块 up-*；不替代产品面

◆ 要点  浏览器永远只打 Caddy。runtime 对浏览器开 SSE，鉴权与游标就绕开 api 了。
◆ 要点  HA 扩 runtime 副本不会复制 bge-m3：权重只在 sources-retrieval。

组件：做 / 不做

web           做  场景工作台；消费 SSE 与 GET /view
              不做 推断 Turn 阶段；直连 runtime

api           做  鉴权、准入、落库、turn.dispatch 门铃、订 live、SSE、投影、Ops、总线 enqueue
              不做 跑 Agent loop
              ◆ 要点  HTTP 202 = 已入队 pending，不是 turn.accepted。

runtime       做  claim/lease、Intake、Engine、工具调度、checkpoint、写耐久事件、PUBLISH live
              不做 对浏览器开 SSE；UI 投影；常驻 ST 权重；startup sources sync（orchestrator）
              inflight 默认 16（waiting_approval 仍计）；满则停领
              软件 16 ≠ 物理 16：热连接池 5×5s 往往先饱和；PG LISTEN（events/commands）另开连接
              bypass 池 5×120s 同实例 PG，给 CASCADE 擦除等慢语句，不是第二台库，也不是 RAG 的 psycopg
              lease 丢且不能安全续跑 → failed(runner_lost)
              claim 超过 15s 无人领 → failed(start_timeout)
              单进程 uvicorn，禁止 --workers；水平扩展靠 runtime 副本（make up-ha）
              回退才是 api HTTP 推 start-turn 到 :8001

sources-retrieval  做  唯一 ST/hash 权重、query/index embed、sources sync/watch、总线消费 sources.index_sync
              不做  Turn Engine；对浏览器开端口

model-gateway 做  live 上游 LLM 流（NDJSON）
              不做 stub/recorded（编排本地）；工具 / embed

sandbox       做  OS 隔离命令执行
              不做 模型 / embed

ast-indexer   做  后台符号表
              不做 进 Turn 热路径；替代 LSP；进入资料检索向量面

bench         做  官方评测；mem_limit 6g（GPU overlay 12g）
              不做 日常用户提问路径

资源量级（make up 单副本 · GPU/bge-m3）

cgroup 名义合计可过 20g（含 retrieval 12g + bench 12g 若同开）；日常产品空闲约数 GiB
postgres / bench-postgres 各 1g
runtime 4g（编排 · remote embed）  sources-retrieval 12g（GPU overlay）或 4g（CPU）
model-gateway 512m · sandbox 1g · api 1g · ast 768m · redis 无硬帽
无 GPU → gte-small@384；VRAM≥8GiB → bge-m3@1024（权重只在 sources-retrieval；bench 可另有评测镜像）
gateway/sandbox 镜像 FROM runtime:slim（~0.7 GB）；retrieval FROM runtime:default（ST bake）

命令    make up（先拉起再只重建 dirty） / make up-all
        主机重启优先 make start；make smoke / make gate
        SWE 环境 make ops-swe-eval-ready
        redis 旁路 make start-redis
