写作：Work 拥有树；新一篇归档旧稿

稿树属于 Work，Session 只保存对话。写作场景的步数、温度、补丁自动应用和检索排除见 writing.yaml（max_steps=40、temperature=0.8、patch_auto_apply=true、attach_writing_signals=true，排除 seed/intel）。Engine 不读取场景名。回读、编辑和修订各自是用户发起的下一次 Turn。模块划分见 写作模块解剖。

  • ◆ 要点 新开一篇时由平台归档旧稿。评分和修补不另开一条 Engine 循环。

稿树（Work 根，不是 Session）

outline.md                 作品纲；volumes/ 卷问题；chapters/ 章便条。旧单文件仍可读
drafts/manuscript.md       正在 upsert 的正文
drafts/archive/            occupy=fresh 时旧稿拷贝处
sources/                   可被 search_sources 的资料（写作默认排除 seed/intel）
sources/cards              writing_cards_dir；风格卡 ≤1800 / 人物 ≤1000 / 情节 ≤600 / 一般 ≤400
                           合计垫底 ≤3600；单卡 ≤2000；走 volatile，不焊进 system
.agent/work/               story_state / editor_notes / author_notes / surface / manifest / patch_budget
工作台可见正文帽 writing_work_surface_max_chars = 6000
写作 GUI 左侧「作品」：有稿时列出大纲、正文、人物；一键清空整篇（含侧车）。资料库仍是引用材料。
◆ 要点  Session compact 不得拆散 Work。切会话 ≠ 换作品根，归档也不该发生在 Session 层。

主链

1  意图分流（wants_new_piece × manuscript_is_occupied）
     「写一篇 / 写个故事」且稿已占用 → occupy=fresh：拷到 archive，unlink 当前稿，focus=ch1
     空工作区不是禁写：`update_outline` / `draft_section` 会创建 outline.md 与 drafts/
     没有 write_file；`propose_patch` 不能建新文件；不要把整章写在聊天里当交卷
     「续写 / 下一章 / 第 N 章」→ upsert 当前 drafts/manuscript.md
     「写一篇章纲」不是新开一篇，除非同时说另/新开
     ◆ 要点  不要让用户先删文件。fresh 是平台归档，不是产品提示「请清空」。

2  开工相位（select_turn_tools，进 while 之前换工具表；命中即停）
     短篇/单篇：纲可选，outline_phase=ready，不闸工具
     长篇：
       选书 → 只留 propose_book_candidates，交卡片后 TERMINATE
       勾选发 select_pond（ponds_id、item_id），对上当前候选才写入已选书
       换一组是 more_ponds，或用户原话「我要其他的」；不拼「采用此开篇」
       等纲 → 只留 update_outline 与 read_file；写入后本轮停，等「写第一章 / 改纲」
       否则写作工具仍在；没有当前章段时 draft_section 被拒绝
     章便条可见字 < 80 且用户未要目录 → outline_thin（80 只表示便条还在，不是质量）
     近池身份看 story_state（≥1 条 rising pressure 且 ≥1 条 info_gap）
     通常不检索；卡片进 writing_cards，不进资料向量面
     事后另一次 Turn，排在选书/等纲之后，与成稿互斥：
       /reread · 回头读读 → reread_book · author_state · propose_retcon；回读包不带分数
       /edit · 审读这一章 → editor_report 只写旗，不改稿
       /revise · 含糊「去掉 AI 味」→ 只留 read_file / grep / glob，点名原句后才改
     ◆ 要点  相位是开工时收白名单，不是 Engine 里新节点。回读、编辑、修订各是用户显式的下一次 Turn。

2b 点选进下一回合。默认 TURN_DISPATCH=pull，意图写在 turns.intent，领取时读出来。

     工作台 useWorkbench.ts
       handleSelectOpeningPond  intent.kind=select_pond    ponds_id、item_id
       handleMoreOpeningPonds   intent.kind=more_ponds     ponds_id
       handleExecutePlan        intent.kind=confirm_plan   plan_id；同时 plan_phase=executing
       handleAcceptPatch        intent.kind=accept_patch   patch_id；message=「采用这个修订」
       handleRejectPatch        intent.kind=reject_patch   patch_id；message=「不用这个修订」
       都进 handleSendText → startTurn（shared/api/client.ts）
       POST /api/v1/sessions/{id}/turns
       body：message、scenario_id、plan_phase（可空）、intent（可空）

     api  routers/sessions.py create_turn
          → services/resource/turns.py create_turn
          _normalize_intent：kind 不是上面五种，或 body 不是对象 → 该列 NULL
          通过则 json.dumps 写入 turns.intent（JSONB）
          列来自 alembic 0034_turn_intent，DDL phase2_turn_intent.sql
          user_input 仍是界面那句短消息

     runtime  controller/turn_dispatch.py
          _load_accepted 的 SELECT 带 t.user_input、t.plan_phase、t.intent
          _intent_from_row 把 jsonb 还原成 dict（库里可能是对象，也可能是字符串）
          try_claim_and_start 调用 start_turn(..., intent=)

     start_turn  controller/turn_controller.py
          租约拿到之后、_run_turn 之前调用 resolve_intent（app/writing/intents.py）

          resolve_intent
            ├─ select_pond
            │    _lookup_pond(ponds_id, item_id)；对不上抛 InvalidIntent
            │    before_apply 先拍影子快照
            │    save_committed_pond
            │    交给模型的消息改为「就用这个开篇：{title}」
            │    原 message 和这句不同时，接在后面
            ├─ more_ponds
            │    load_opening_ponds 的 ponds_id 必须是这一组
            ├─ confirm_plan
            │    load_turn_plan 的 plan_id 必须是当前计划
            │    返回相位 executing
            │    preferred_plan_phase：用这个 executing，不用调用方带来的 planning
            ├─ accept_patch / reject_patch
            │    latest_pending_patch 的 patch_id 必须相同
            │    放弃：快照写完再 drop_pending_patch
            │    文件 .agent/work/pending_patches.json
            └─ InvalidIntent
                 _fail_turn
                 termination_reason=fatal_error
                 error_kind=invalid_intent
                 message=「这个选择已经失效，请重新点选。」
                 工作台 httpErrors.ts 的 turnFailureUserMessage 见到这个 error_kind 就显示这句

     快照  before_apply → _intent_baseline → policy/shadow_git.py intent_baseline
           → ensure_turn_baseline，tag 名 turn/{turn_id}
           tag 已经有就返回，Engine 里后一次 ensure_turn_baseline 不会覆盖
           本地接头 writing_host/runner.py 用 snapshot_turn，同样在 resolve_intent 写入之前

     折叠  useWorkbench 把事件列表交给 reduceTurn（shared/workbench/reduceTurn.ts）
           busy 时界面上的 plan、开篇、用量、修订候选、钉住卡片用这份结果
           回合结束且 GET TurnView 的 artifacts 非空，改用 artifacts
           turn.token、turn.thinking.delta、section.draft.delta 进 streamDeltaBuffer，不进 reduceTurn
           单测输入是 packages/contracts/tests/fixtures/turns/ 的 events，期望是同文件的 view

     注: client.ts 里的 acceptPatch、rejectPatch 还在。工作台按钮不调用。评测仍走回合内那条命令。

3  成稿 draft_section(fragment=…)
     冷起步无纲职 → fragment=mixed（不要发明章类型当评分切片）
     有纲职 → infer_fragment_from_duty（情节/质地/高潮/动作/对白）
     按需 search_sources（cite；每 Turn ≤3；超限拒绝本次调用）
     禁止每轮强制 RAG、禁止 Turn 末自动 judge
     篇幅：用户点名 N 字优先；否则短篇目标 2500 · 单篇目标 3500 · 长篇章稿 3000–5000
       实体文字 = 不含空白；无名额章稿可见字 <3000，或点名 N 字不足 85% → length_short
     返回值带 L0 旗 + L1 writing_signals；作者档不注入 L0 receipt
     append：短篇/单篇过程 L0 未清不得 mode=append；长篇 L0 不挡加厚
     交付门只看篇幅：短篇/单篇 length_short 不得宣称已完成；长篇只挡本章 <800 字
     配额未满不要默认 append 第二场

4  过程 L0 或 length_short → 同轮 propose_patch(repair_span)
     写作场景 patch_auto_apply=true，仍须 UI 出示 diff
     只换检测岛里的 old_text；碎拍取最密岛，不把最弱评分窗升成整窗
     net 低只观测，不出 span。编辑札记在下一章
     同岛停（对上一次已生效的岛 overlap ≥12）；下一岛仍 propose_patch；每 penalty key 2 次 / 章合计 3
     无差或岛未碰 → 不计次数；小岛尽才 rewrite_window（每章 1，≤160 实体字）
     宽窗 / rewrite 尽 → 停修（长篇本章可交）
     连续 apply miss 2 次停
     默认不附平台 neighbor；碎拍且有本书 beat 时才附
     不整章再 draft_section（length_short 加厚除外）
     hygiene 拒绝对白改旁白
     ◆ 要点  修补焊在 tool_result，不改 Engine while。做成「自动再跑一轮润色」会把 pass 变成隐式流水线。

5  落盘 drafts/manuscript.md
     回读 / 编辑 / 修订 / 导出仍是用户下一次 Turn
     Session compact：书签记 focus / 稿面预览；交付门说明书不进 last_output_preview
     抽卡：人名须能从动作上站出来，不把「临时安置点」拆成假角色
     post_turn_jobs: sources.index_sync（不挡下一 Turn 首 token）

Writing spec（易变垫底，≤620 字）

build_writing_spec_block → volatile_context，不进 system 提示（prefix cache）
  book_scope  short|single|long     「写一篇」优先于题材词；可在 writing_prefs.json 钉死
  regime      长篇默认 author；短篇/单篇永远 strict
              句内「作者模式 / 严格模式」优先；作品面板可钉同一份 prefs
              作者档不注入 L0 receipt。work_mode 权重仍钉在工具里，不在设置页
  work_mode   经典文学 / 连载网文    金标分库；学拍不搬核
  fragment    评分切片，不是章职
  focus / 这一场 / outline_phase     short/single=`ready` · 长篇未立定近池=`open`（propose_book_candidates；点选认 id，或原话「我要其他的」） · 已立=`continue`
  无纲时写「新篇另起人与事」
◆ 要点  风格写入规格，不作为开工条件。只给出题材或要求「看看」时，先提交 start_kind 不同的近池卡片。更换职业或地点不算另起一篇。
