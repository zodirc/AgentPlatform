请求主路径（端到端）

客户端提交 Turn 之后，业务首事件不是 HTTP 202，而是编排 runtime claim 后发出的 turn.accepted。Turn 分发仍走 Postgres 门铃；进 Engine 后 live 模型 / query embed / shell exec 分别 HTTP 打到独立容器（model-gateway · sources-retrieval · sandbox）。闸与容量见「时序 · 并发 · 负载」；本页只串端到端。

  • ◆ 要点 设计取舍：漏了会用 HTTP 202 当 TTFB、把编排当胖 runtime、或把 Redis 当成首 token 通道

逐步经过

t1  工作台 POST /sessions/{sid}/turns   Cookie + JSON
    Caddy  /api/* → api:8000；HTTP/1.1 短请求，无流式语义，不验 Cookie
    api    鉴权 · assert_session_owner · 校验 work/scenario
           未领取队列满 → 429 + Retry-After:5（Turn 未插入）
    ◆ 要点  429 时没有 turn_id。客户端不得拿「上一次失败的假 id」去挂 SSE。

t2  同一事务  INSERT turns(pending) + runs(accepted, pull_eligible)
              + turn_views seed
              COMMIT 后 pg_notify(turn_dispatch_channel, run_id)
           响应 202 { turn_id, run_id, status: pending }
           浏览器此时可开 SSE；流上还没有 turn.accepted，只有空闲 ping
    ◆ 要点  202 = 已入队。把 202 当「runtime 已开工」，排队会被算进推理时延。

t3  编排 runtime claim（与浏览器无 TCP）
           条件 UPDATE 抢到 accepted run；写入 lease 180s
           StartSpec：场景、计划相位；评测另带无人值守标记与模型密文
           INSERT turn.accepted（通常 sequence=1）→ NOTIFY turn_events_channel(turn_id)
    ◆ 要点  业务首事件在 claim 之后。TTFB 从 SSE 见到 accepted 起算，不是从 POST 返回起算。

t4  Intake（确定性；零或一次 compact 模型）
           InputCompiler：斜杠、@path prereread（≤3 文件、各 1.2k 字、0.4s）
           拼接 session transcript；无 transcript 的旧会话才塞 context_summary
           should_query=否（/help /compact /verify）→ 直接 turn.completed(local_response)
           需要模型 → 首轮由模型决定直答或 tool_use；scenario_id 不由模型推断
    ◆ 要点  斜杠短接在 Controller。把 /help 送进 Engine while 会占 inflight 16 里的一颗。

t5  Engine while（编排进程）内关键节点 append-only 写 turn_events
           assemble → ModelGateway.stream → 解析 → tools / 终局
           live 模型  ──HTTP NDJSON──► model-gateway ──► 上游 Provider
           query embed──HTTP──────► sources-retrieval（唯一权重池；不上 Redis）
           shell/tests──HTTP──────► sandbox（bwrap/landlock；可回退本进程）
           token / thinking.delta 经 BufferedEventWriter ~40ms 窗；非 delta 先刷缓冲
           每行 advisory lock 下单调 sequence
           api 一根 LISTEN fan-out → SSE 按序号回放 + UPSERT turn_views
           thinking.delta 默认不进 view
    ◆ 要点  while 形状仍在编排；重活已拆到平面容器。首 token / query embed 禁止上 Redis Streams。

t6  工作台只消费 SSE 与 GET /view
           UI 不推断阶段；断线 Last-Event-ID / since_sequence 续传（闷流 45s，≤8 次）
           approval.requested 关 SSE；批准走短 POST，不靠这条 GET 挂着执行
    ◆ 要点  runtime 不对浏览器开流。Turn 事实桥是 Postgres；平面热路径是 HTTP；异步索引才是 Redis。
