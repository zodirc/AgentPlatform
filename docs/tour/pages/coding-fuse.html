编码 Turn：从读题到交卷

模型已会调用 search_codebase、edit_file、run_tests。平台不另发明导航工具，而是在返回值中写入模型无法忽视的事实。官方是否判通过看 Docker 内隐藏测（resolve_rate），不是看这些探针是否为绿。结构车道只在 agent Profile；写作/情报根本不装这套工具。

  • ◆ 要点 设计取舍：漏了会把探针绿当官方分、把 grep 词面当定义、或为「再验一轮」加第六个图节点

主链（仍是 Engine while，虚线汇入 tool_use）

1  读题  extract_issue_repro_hints(problem.md / PROBLEM.md / issue.md)
     抽出符号名、报错串、代码块、REPL、raises
     上限：命令 4 · 标记 8 · token 6 · 资产 2 · 信号 6 · fence 400 字
     禁止先 list_dir(".") 枚举仓库根（写在 scenarios/agent/system.md，由返回值落实）
     隐藏 F2P / gold patch 不进 Work
     ◆ 要点  抽取器只能看见 issue 写过的例子。把 F2P 名字塞进 prompt，测的是泄漏。

2  复现  用 issue 内最小例子；改完必须再跑同一条命令
     仓库 pytest 全绿只武装 issue_repro_armed
     覆盖判定：issue_repro_edits_since == 0（最新一次成功 edit/write 之后）
     失败签名仍在 stdout → 不算清；写再读须同一套 format/kwargs；casefold 主张须再跑折叠变体

3  找定义  search_codebase（Locate）
     符号表粗筛 top_k=5 → LSP 在标识符列确认 → 只有确认过的进 definitions[]
     grep 符号形 pattern → handler 整条改道（redirected_from=grep），工具名不变
     词面 hits 不得冒充定义；模块名/形参查空 → locate_incomplete，不是索引故障
     产品对话不等 AST ready；索引默认入队 work_ast_index_jobs（inline 仅测试）
     ◆ 要点  符号表无向量。写作打开 Locate，会把散文专名当代码符号。

4  就地改  edit_file 替换一小段（非唯一命中回显最多 5 个 span）
     32k 截断时附大纲
     模型拿完整 result；Ops 侧 tool.completed 只落瘦 meta
       impact / checks（单文件增量，最多 20 条，超时 30s）
       related_tests 最多 5 条 + python -m pytest {path} -x -q
     平台不代跑相关测试（启发式 250ms / import 反向 400ms）
     ◆ 要点  代跑会把探针绿和官方 resolve_rate 混在一起。

5  改完再验  checks · related_tests 命令 · 邻文件 read_lints · 同一条复现
     失败摘要从未截断全文抽 first_failures（入 state 再截 400 字）
     评测路径剥 | tail，送进该题 sweb.eval；宿主树上的绿不算
     pip/uv install 在 SWE 镜像内拒绝

6  终局边  欠验证 → verify_receipt continue 同一 while
     剩余步数 < 10 则省略；每类每 Turn 至多一次
     不是新图节点；菜单不可见
     ◆ 要点  探针全绿仍可能 harness unresolved（14365：issue 无小写 NO，隐藏 roundtrip 仍红）。

超时与文件帽是配置，不是能力开关。Capability 在 Profile.tool_names。structural_prewarm 不挡 TTFB。
