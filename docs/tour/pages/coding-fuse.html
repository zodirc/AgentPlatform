编码场景

编码场景使用 agent Profile，max_steps 为 150。用户消息给出本轮任务，源文件位于该 Work 的工作区。定义与引用由符号表和语言服务提供，测试与 shell 在 sandbox 中执行。

  • ◆ 要点 写盘与执行分开。edit_file 不运行被修改的代码，建议的测试命令留待后续调用执行。
部分职责
用户消息本轮任务。Controller 将其写入 turn_user_text。定义查找不读取该字段。
符号表扫描工作区源文件，为函数名、类名建立索引，供定义查找取出候选。
语言服务在源文件的行、列上确认定义，查询引用，并参与诊断。
edit_file在编排进程中修改工作区里的已有文件。不执行这段代码。
run_tests / run_command在 sandbox 中执行。sandbox 不可用时拒绝。

符号名判定

is_symbol_query 只检查这一次传入的字符串。空串与超长在前，空白次之，正则元字符再次，最后才接受标识符。

字符串后续路径
空，或长度大于 128文本搜索
含空白，如 TypeError: login failed文本搜索。报错原文属于此类。
含 \ ^ $ * + ? { } [ ] | ( )，如 foo.*bar文本搜索。这些字符按正则处理，不用于查定义。
整段为标识符或点分路径，如 login、Card、pkg.Class.method定义查找：符号表取候选，语言服务确认。

文本搜索将正则字符转义为普通字符后，在文件正文中做子串匹配，位置写入 hits，definitions 为空。locate_incomplete 为假，表示本次未尝试查找定义。定义查找若未得到语言服务确认的位置，definitions 同样为空，locate_incomplete 为真。

符号表

索引记录函数、类所在的文件。冷启动写入 work_ast_index_jobs，由 ast-indexer 另进程消费，不阻塞本轮。文件变更后的刷新去抖为 0.5 秒。一次查询至多返回 5 个同名候选。索引中尚无该名字时，按名称末段匹配文件名，例如 Card 对应 Card.py，上限 8 个文件、200 个目录，不等待整库索引完成。

编码 Profile 的 structural_prewarm 为真时，Controller 在后台预热语言服务，StartTurn 不等待预热结束。对符号名调用 grep 时，处理函数改走定义查找，工具名仍为 grep。

语言服务

符号表给出候选后，语言服务按该文件的路径、行、列确认是否为定义。确认结果写入 definitions，并停在第一个确认成功的候选。导航超时默认 15 秒。语言服务不可用、超时、缺少提供者或语言不受支持时，本次定位失败；符号表候选可留在 candidates，不进入 definitions。

索引没有结果或调用失败时，改为直接调用 goto_definition。没有结果包括：当前没有 Work、索引未启用、索引状态为 ERROR、按文件名也未命中。直接调用仍无位置时，退回文本搜索，locate_incomplete 为真。self、cls、args、kwargs、msg、exc、err 以及全小写点分模块路径，原因记为 non_definition_query，其余记为 no_workspace_symbol_match。

写盘

old_text 在目标文件中须恰好出现一次，new_text 只替换该处。出现 0 次时不写盘，并返回至多 5 条邻近候选。出现多次时不写盘，并返回出现位置，至多 20 条。新文件使用 write_file。写盘前比较新旧文本的语法，新引入的语法错误拒绝写入。快照写成时，此次写入按可回退直接放行；快照未写成时等待批准。edit_file 不读取定位结果，definitions 为空不构成拒绝写盘的条件。

写盘成功后，同一次结果附带下列三项。平台不据此再改一稿，也不执行其中的测试命令。

附带内容来源与限度
引用从 old_text 与 new_text 中抽出一个符号，由语言服务列出引用位置。路径不是代码，或片段中没有符号，则跳过。
新增诊断比较写盘前后的诊断，只保留新增项。默认至多 20 条，超时 30 秒。
测试命令至多 5 条，形式为 python -m pytest {path} -x -q。按文件名查找的预算为 250 毫秒，按 import 反向查找至多 250 个文件、400 毫秒。

跨文件诊断由模型另行调用 read_lints。该工具合并 ruff 与语言服务的诊断后返回。

sandbox 中的执行

读文件与改文件由编排进程直接访问工作区。sandbox 可用，指已配置远程 sandbox 平面，或本进程的 bwrap 可用。编排进程未配置 SANDBOX_PLANE_URL，或隔离探针失败时，run_tests 与 run_command 被拒绝，原因为 sandbox unavailable。

调用执行条件
run_tests仅接受 pytest、python -m pytest、npm / pnpm / yarn test、npx vitest、npx jest。其它字符串拒绝，不进入 shell。sandbox 可用时允许执行，可写范围为当前工作区根。
run_command用于构建、安装及其它命令。sandbox 可用且命令在允许列表中时直接执行；不在允许列表中、且不属于评测命令集时，先经批准。单文件的 cat、head、tail、sed -n，且命令行不含管道时，改为 read_file，不进入 shell。

编辑之后尚未运行测试

代码文件编辑成功后，verify_pending 置为真。非代码路径，或引用与诊断均被跳过时，不置该标记。随后一次被接受的 run_tests，或被判定为测试的 run_command，将该标记清掉。被拒绝的测试命令不清。

模型本次只返回文本、未再调用工具，且剩余步数不少于 10 时，引擎追加一条用户消息：写明本轮改过的代码文件数、最后一次编辑后尚未运行测试，并附上已收集的测试命令与上一次失败摘要。摘要截断至 400 字。追加之后 continue，进入同一次 while 的下一步。cancelled 或 budget_exceeded 时不追加。
