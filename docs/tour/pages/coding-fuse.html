编码工具调用链

这一页按一次编码调用的实际顺序写：search_codebase 分流、locate_via_ast_index 确认、edit_file 写回、run_command / run_tests 进沙箱、模型只回文本时的 run_product_verify_hook。字段写在触发它的那一步。Profile 为 agent，max_steps 为 150。

1. search_codebase（tools/core/codebase_search.py）

模型调用 Locate 时进入 search_codebase(query, path=".", limit=20)。query 先 strip，再交给 is_symbol_query（structural/symbols.py）。判定只看这一次字符串，不读 turn_user_text。用户消息里的报错因此不会自己变成符号查询。

search_codebase(query, path, limit, turn_id)
  │
  ├─ is_symbol_query 为假
  │    └─ _lexical_codebase_hits
  │         pattern 经 re.escape 后做子串
  │         无命中且 query 含空白 → bm25_file_hits；仍无则 repo_map
  │         写入 mode=lexical，definitions=[]，locate_incomplete=false
  │
  └─ is_symbol_query 为真
       └─ locate_via_ast_index（有 Work、索引启用、状态不是 ERROR）
            返回 None → 直接 goto_definition
            语言服务基础设施失败 → definitions=[]，locate_incomplete=true，不把词法命中写成成功定位
            确认到位置 → mode=symbol，locate_incomplete=false
            确认不到 → 词法 fallback，locate_incomplete=true
                 self/cls/args/kwargs/msg/exc/err、全小写点分模块路径
                   → locate_fuse_fail_reason=non_definition_query
                 其余 → no_workspace_symbol_match

is_symbol_query 的顺序是空串与长度、空白、正则元字符，最后才是整段标识符。栈和正则若走定义查找，得到的是空 definitions 加 locate_incomplete=true，正文位置不会留下。所以这两类在入口就改走词法，locate_incomplete 保持 false。

query分支写入
空，或长度大于 128词法hits 为子串位置，definitions=[]，locate_incomplete=false
含空白，如 TypeError: login failed词法；无命中再 BM25同上。无 BM25 命中时附 repo_map
含 \ ^ $ * + ? { } [ ] | ( )，如 foo.*bar词法元字符先 re.escape，按普通字符做子串
整段标识符或点分路径，如 login、Card、pkg.Class.method符号语言服务确认后才写入 definitions

两条路都可以让 definitions 为空。词法的 locate_incomplete 为 false，表示没有尝试查定义。符号路径没有确认到位置时，同一字段为 true。

2. locate_via_ast_index（structural/workspace_index/locate.py）

冷索引不挡本轮。workspace_ast_inline 默认 false，建索引写入 work_ast_index_jobs，由 ast-indexer 另进程消费。文件变更经 notify_path_changed 去抖，workspace_ast_dirty_debounce_seconds 默认 0.5 秒。编码 Profile 的 structural_prewarm 为真时，语言服务在后台预热，StartTurn 不等它结束。

没有 work_id 或 owner、索引对该 Work 未启用、lookup 无 meta、或状态为 ERROR 时，函数返回 None，search_codebase 改调 goto_definition，不再经过符号表。

lookup_symbol 先取候选，limit 至少为 max(top_k, 20)，workspace_ast_locate_top_k 默认 5。没有 postings 时调用 _instant_def_hits：用名称末段对文件名（Card 对 Card.py / card.py），目录遍历上限 200，文件上限 8，只解析这些文件，不造定义。文件名也没有，返回 None。有 path 且不是 "." 时，候选再按该前缀过滤。

剩下的候选按 _rank_symbol_hits 截到 top_k。对每一个：文件不存在则标删除并跳过；投影与磁盘 size / mtime / content_hash 不一致则 parse_single_file_fallback 校正行列，校正后仍无同名符号则标脏并跳过。列号经 _snap_hit_col 收到该行标识符上（优先 def / class 形式），再 goto_definition(path, line, col)，超时 structural_nav_timeout_s 默认 15 秒。

确认到 locations 即停止，不再确认后面的候选。写入 definitions，locate_incomplete=false。未确认的同名留在 candidates（confirmed=false，source=ast_index），不进入 definitions。同名可以出现在多个文件；候选若直接写入 definitions，下一次编辑会按错误路径改。edit_file 不读这个字段，定位失败不会否决一次已经带 old_text / new_text 的写入。

语言服务返回处理
lsp_unavailable / provider_missing / unsupported_language立刻结束。 definitions=[]，locate_incomplete=true，_ast_infra_failed。候选可以留下
timeout / cancelled试下一个候选。全部失败则 locate_fuse_fail_reason=lsp_timeout
有 locations写入 definitions，停在这一处
无 locations，且没有基础设施故障definitions=[]，locate_incomplete=true，原因 definition_null。上游再做词法 fallback

3. 符号形 grep（tools/core/read_tools.py）

grep(pattern) 在 is_symbol_query(pattern) 为真时调用 search_codebase，并写 redirected_from=grep。注册的工具名仍是 grep。同时再做一次 escape=True 的词法扫描，结果放进 lexical_hits，并覆盖返回里的 hits。definitions 仍只来自 Locate。标识符因此不会只剩一页文本命中；文本命中以 lexical: true 附在旁边。

4. edit_file（tools/core/edit_tools.py）

写盘在编排进程里做，不进沙箱，也不执行被改的代码。入参是 path、old_text、new_text；edits 为列表时按多个 span 处理，否则用这一对 old_text / new_text，replace_all 来自同名参数。新文件不走这里，走 write_file。路径被 write_path_block 挡住，或 new_text 被 gate_write_content 挡住，当次返回，不读文件。

edit_file
  │
  ├─ 文件不存在 → error「File not found」，不创建
  ├─ read_bytes → load_text_bytes
  │    探测 BOM、多数派换行（CRLF 多于裸 LF 则记 \r\n）
  │    utf-8 能往返则用 utf-8；否则用文件内声明的 coding
  │    解码后再编码与原字节不一致 → error=unsupported_encoding，status=rejected，不写
  │    不把非法字节换成 U+FFFD
  │
  ├─ plan_spans（匹配在 LF 归一化后的 text 上）
  │    structural_match_trailing_ws 默认 true
  │    structural_match_reindent 默认 false
  │    任一 span 失败，或 span 重叠 → 整次不写
  │
  ├─ apply_spans：从后往前替换，前面的偏移保持有效
  ├─ check_syntax_gate：新文本比旧文本多出的语法错误 → error=syntax_error，不写
  ├─ dump_text：按原编码、原 BOM、原换行写回 write_bytes
  └─ notify_path_changed
       然后并行：引用（impact）、写盘前后诊断差（checks）、related_tests

匹配在 LF 文本上做，写回恢复原编码和多数派换行。模型没改的字节留在磁盘上，diff 里不会因为换行或编码多出一整文件。structural_match_reindent 默认关：打开后 _reindent_replacement 把 new_text 的行首空白挪到命中块的缩进上，请求里没有写出的空白会进文件。structural_match_trailing_ws 默认开：多行 old_text 只差行尾空白时仍能定位。

plan_spans / 写回返回磁盘
编码、BOM 或换行无法原样往返unsupported_encoding，applies=false不写
old_text 0 次old_text not found，邻近候选至多 structural_span_candidates（默认 5）不写。上次读取之后文件已变，summary 附加 File changed since last read.
多于 1 次，且该 span 的 replace_all 为假old_text matches N times，出现位置至多 20 条不写。要改每一处须该 span 自带 replace_all
span 区间重叠overlapping edits不写。替换顺序不会决定最终字节
新文本引入语法错误syntax_error，带 path:line:col不写。下一轮符号表和诊断仍解析写盘前的文件
通过Edited {path}，附 impact / checks / related_testswrite_bytes 已完成

影子快照写成时，这次写入按可回退放行，不必再等一次批准。快照没写成时，写入本身不因此失败，但不能凭可回退放行。记录在工作区旁边的 .agent-shadow，不改用户仓库里的 .git。

写盘成功后同一次结果附带三项。平台不按这三项再改文件。

字段从哪来限度
引用 impact第一个 span 的 old_text / new_text 抽一个符号，语言服务列引用路径不是代码，或片段里没有符号，则跳过
诊断 checks写盘前 _checks_for_edit 与写盘后的差，只留新增项默认至多 20 条，超时 30 秒。跨文件诊断另一次 read_lints（ruff 与语言服务合并），不放进这次返回
related_testslanguage_for_path 有登记才查。related_tests_for_path，命令模板 python -m pytest {path} -x -q至多 5 条。文件名查找 250 毫秒；import 反向至多 250 个文件、400 毫秒。登记含 Python、TypeScript、JavaScript、Go、Rust。命令字符串仍是 pytest。登记内的代码文件编辑成功会把 verify_pending 置真；Go / Rust 上这条命令不能当作该语言的测试运行器

5. run_tests / run_command

读文件和改文件由编排进程直接访问工作区。这两条调用必须进入 sandbox。未配置 SANDBOX_PLANE_URL，或隔离探针失败时，返回 sandbox unavailable，不在宿主机上执行。

run_tests 只接受 pytest、python -m pytest、npm / pnpm / yarn test、npx vitest、npx jest、go test、cargo test。其它字符串拒绝，不进 shell。允许时，可写范围是当前工作区根。

产品 run_command 在 bwrap 里 --unshare-net。沙箱内 127.0.0.1:3128 经 Unix 套接字连到宿主机代理。包注册表与 GitHub 的 80/443 只读访问直接放行；其它主机记入 egress_denied，须带 egress_hosts 再请批准，批准范围是这一次列出的主机。评测回合不启代理，也不共享网络。用户批准 sandbox_relax 之后才 --share-net。工作区的构建、测试、格式化，在沙箱就绪且不是评测时可以直接执行。单文件的 cat、head、tail、sed -n，且命令行不含管道时，改为 read_file。

6. 模型只回文本（engine/agent_engine.py → run_product_verify_hook）

本步没有 tool_use、助手消息已经是文本时，引擎在把文本写入 messages 之后调用 run_product_verify_hook（engine/product_finish.py）。条件同时满足才执行：scenario_id=agent、不是 ops_eval、product_post_edit_hook 为真（默认开）、本 Turn 尚未跑过、verify_pending 为真、related_tests_union 里有命令。命令取路径字符串最长的一条，经 run_tests 进沙箱。结果写成一条用户消息（product_verify_hook，含 command / status / summary 前 800 字 / delta），然后 continue，回到同一次 while。每 Turn 一次。product_hook_ran 在调用前就置位，这次执行失败也不会在同 Turn 再跑。

钩子没有跑，并且剩余步数不少于 verify_receipt_reserve_steps（默认 10）时，再追加一条用户消息：本轮改过的代码文件数、编辑后尚未运行测试、已收集的测试命令、上一次失败摘要（截断 400 字），然后 continue。10 步留给再跑一轮模型并至少再试一次测试。cancelled 或 budget_exceeded 不追加。

代码文件编辑成功把 verify_pending 置真。非代码路径，或引用与诊断都被跳过时不置。随后一次被接受的 run_tests，或被 is_testish_command 判为测试的 run_command，把标记清掉。被拒绝的测试命令不清。
