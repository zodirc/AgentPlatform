ascii.qdp Table format assumes QDP commands are upper case
### Description

ascii.qdp assumes that commands in a QDP file are upper case, for example,
for errors they must be "READ SERR 1 2" whereas QDP itself is not case
sensitive and case use "read serr 1 2".

As many QDP files are created by hand, the expectation that all commands
be all-caps should be removed.

### Expected behavior

The following qdp file should read into a Table with errors, rather than crashing.

read serr 1 2
1 0.5 1 0.5

### How to Reproduce

Create a QDP file:

> cat > test.qdp
read serr 1 2
1 0.5 1 0.5
<EOF>

> python
>>> from astropy.table import Table
>>> Table.read('test.qdp', format='ascii.qdp')
ValueError: Unrecognized QDP line: read serr 1 2

命中定义

信号是命中吗为什么
非空 git diff（patch_rate）否乱改也能有 diff。第4–6轮都是 1.0，14365 仍 unresolved。
fuse_ok / 找到定义否找对文件不等于修对隐藏测。
issue 例子再跑过否例子在 issue 里；隐藏测可以是没写的 test_roundtrip[True]。
verify_receipt / test_summary否平台催验，模型可以不理。出口线 ≥0.6 是过程目标。
harness resolved是F2P 全部过 且 P2P 全部过。与排行榜同一把尺。

为什么不自己在工作区跑测试当分数？Lite 每题环境不同；工作区只是源码 checkout。错误解释器上绿，评委镜像里仍红。

审阅偏差。 n5 全 astropy，不能外推到 django 占多数的 Lite（n25 才开始有 django）。同分异题：4/5 可以是「换了一题过、一题回落」，不是能力稳定在 80%。第6轮换模后仍是同一题未过。无人值守预批准比真实用户少一道审批摩擦。
