issue 例子覆盖义务

这条义务挂在成功的代码编辑之后。edit_file 成功后，_ensure_issue_repro_hints 才读工作区根的 problem.md / PROBLEM.md / issue.md，每 Turn 一次。三份都不在，文本为空，收据不武装。官方评测由 repo_materialize 把 problem_statement 写成 problem.md。抽取范围限于正文里已经写过的例子，隐藏测试不进 Work。仓库测试通过之后，这些例子仍须在最新一次代码编辑之后被成功命令覆盖（issue_repro_edits_since == 0）。

  • ◆ 要点 只抽取 issue 正文中已经写明的例子。覆盖判定绑定最近一次编辑。

抽取与覆盖判定

抽取（load_problem_text → extract_issue_repro_hints）
  优先：围栏代码块、引用命令、REPL（>>>）、输入输出样例、raises 行、Expected 小节
  表路径：Table.read/write 的 format= 与 header_rows= 会进入 roundtrip_kwargs
  ASCII 格式名（ascii.xxx）同样武装写再读
  大小写主张：not case sensitive / case-insensitive / all-caps 命令 等 → need_casefold
    另生成 casefold_assets，必须用折叠变体再练一遍
  上限：命令 4 · 标记 8 · token 6 · 资产 2 · 信号 6 · fence 400 字 · 资产最短 8 字
  这些列表进 TurnState，随 checkpoint 恢复

覆盖判定（obligations_met_for_command / is_clearing_repro_result）
  成功命令必须吃掉 required_tokens / assets；失败签名若仍在 stdout/stderr 里，不算清
  绿测试（is_green_test_result）只武装「仓库测已过」，同时把 issue_repro_armed 打开
  之后每一次成功 edit/write 把 edits_since += 1；必须再跑覆盖命令才能回到 0
◆ 要点  义务绑最新一次编辑之后。曾经跑过例子不算数；最新一次 edit/write 之后必须再跑覆盖命令。
◆ 要点  抽取器看不到隐藏测。casefold 门只能逼 issue 写过的大小写主张；issue 没写的 roundtrip 变体逼不出。
