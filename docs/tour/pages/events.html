事件拉取：耐久 PG + 活流 Redis → SSE / view

Turn 耐久事实源是 append-only 的 turn_events（编排写入）。高频 delta 默认走 Redis turn.live.*（可丢）；重连靠 turn_views + 耐久 sequence，不保证逐 token 续播。NOTIFY / Pub/Sub 都是门铃：payload 只有 UUID，叫醒后 SELECT 或 drain live。Postgres 是 Turn 真源与 claim；平面热路径是 HTTP；异步索引是 Redis Streams。

  • ◆ 要点 设计取舍：漏了会把 NOTIFY/Pub/Sub 当队列、用 Streams claim、或把活流当成可恢复真源

三条桥（不要画成一条）

Postgres   真源 · CAS/lease · 耐久 turn_events · turn_views · run_commands
HTTP       编排 → model-gateway / sources-retrieval / sandbox（热路径）
Redis      turn.dispatch 门铃 · turn.live.* 活流 · agent.jobs 异步索引
禁止       Streams/XACK claim；首 token / query embed 上 agent.jobs
◆ 要点  「跨服务」有三条。本页主链讲 Turn 事件与活流。

写入路径（编排 runtime）

耐久事件只追加、不改旧行；每行 per-turn monotonic sequence
  AFTER INSERT → pg_notify('turn_events_channel', turn_id)（投影唤醒）
  create_turn COMMIT 后 → PUBLISH turn.dispatch run_id（TURN_DISPATCH_WAKE 默认 redis）
    ◆ 要点  门铃可丢；poll + CAS 保证领取。禁止把 token 塞进门铃 payload。

事件分层 EVENT_DURABILITY
  耐久：accepted / tool.* / 审批 / 终态 → turn_events
  活流：turn.token · thinking.delta · tool.delta · section.draft.delta
  checkpoint（默认）：PUBLISH turn.live.<turn_id>；失败则降级写 PG
  all：仍走 BufferedEventWriter 批写 PG（回滚旋钮）

BufferedEventWriter（仅 EVENT_DURABILITY=all）
  窗默认 0.04s；非 delta 先刷缓冲；advisory lock + MAX(sequence)+1
  EVENT_BATCH_WINDOW_SECONDS=0 可逐条
  ◆ 要点  checkpoint 模式下 delta 默认不进 PG，批窗不再是主路径。

thinking.delta 与租约/stall 的耦合
  Ops 评测：ops_eval_persist_thinking=False → sidecar JSONL + 心跳
  产品 checkpoint：thinking 走 live；非 delta 仍立即落库供 watchdog

读出路径（api）

进程启动
  独立 asyncpg.connect LISTEN turn_events_channel（耐久投影 / 反熵；不占热池）
  PSUBSCRIBE turn.live.*（活流扇出；TURN_LIVE_FANOUT_ENABLED）
  耐久 NOTIFY → 投影队列 UPSERT turn_views（无 thinking.delta / 无 live delta）
  ◆ 要点  活流不经「先 INSERT 再 SELECT」。耐久仍一根 LISTEN 叫醒 N 路追赶。

SSE  GET /turns/{id}/stream
  drain live 信封（sequence=null；SSE 省略 id）+ SELECT sequence > cursor
  data = 契约信封 JSON；游标三处共用：SSE id · Last-Event-ID · since_sequence · 快照（仅耐久）
  空闲 2s poll（反熵）
  ~14s 注释行 : ping；45s 无字节视为闷流，带 since_sequence 重连（≤8）
  终态或 approval.requested 关流
  ◆ 要点  重连不保证逐 token。SSE ⊈ inflight。

GET /view
  列表 / 首屏 / 重连 / 终态；可 ETag/304
  UI 不推断阶段：阶段只来自已持久化的耐久事件类型
  快照不含 live delta

信封（契约，SSE data 与行存储 / 活流）

packages/contracts/schemas/events/envelope.json（0.3.13+）
  共用字段：event_id · stream_id · type · turn_id · run_id · ts · payload
  耐久：sequence ≥ 1；禁止 live_seq
  活流：live=true · sequence=null · live_seq≥1
  type 枚举见 types.json（phase0 开工/工具/终态；phase1 流式/审批/补丁；phase2 用量/检索/组窗）

payload 上限（打破则校验红）
  turn.token / thinking.delta / section.draft.delta    delta ≤8192
  tool.completed.summary / turn.completed.summary      ≤4096
  turn.accepted.user_input_preview                     ≤256
◆ 要点  客户端 JSON.parse 的是信封。按供应商 SSE 原始帧去续传，游标对不上。

无分布式事务时如何自洽

runtime 写  事件、执行态、checkpoint、transcript 真源（编排；不持 ST 权重）
api 写      快照、对外 SSE、常异步的 sessions.context_summary；可 enqueue Redis 索引
短暂落后    以 turn_events.sequence 为序 reconcile；禁止用「api 内存里最新 token」回写 runtime
schema      event_payload_validation 默认开；高频 delta 默认轻量校验（R3），CI 可开 strict
tool.completed summary 最大 4096 字（OpenAPI maxLength）；delegate 大摘要必须 clamp
◆ 要点  没有 XA。领域表（turns.status）可以晚于事件。读 UI 以事件序为准，不要以 turns 行推断「正在想」。
