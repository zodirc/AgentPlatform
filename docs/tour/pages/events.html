事件拉取：NOTIFY → LISTEN → SSE / view

Turn 事实源是 append-only 的 turn_events（编排 runtime 写入）。编排不对浏览器开 SSE；api 不对编排开进程内 channel。NOTIFY 是门铃：payload 只有 UUID，叫醒后 SELECT。丢失时 2s 轮询兜底——SELECT 才是真。Postgres 是 Turn 事实桥，不是全栈唯一跨服务桥：平面热路径是 HTTP；异步索引是 Redis Streams。

  • ◆ 要点 设计取舍：漏了会把 NOTIFY 当队列、把 Postgres 当成 Redis/HTTP 的替代品、或把 40ms 窗当成可以乱序

三条桥（不要画成一条）

Postgres   Turn 分发门铃 · turn_events · run_commands · CAS / lease
HTTP       编排 → model-gateway / sources-retrieval / sandbox（热路径）
Redis      agent.jobs（异步 sources.index_sync 等）
禁止       首 token / query embed 上 Redis；把平面 HTTP 结果当 NOTIFY payload
◆ 要点  「跨服务」有三条。本页主链只讲 Turn 事件那一条。

写入路径（编排 runtime）

关键节点只追加、不改旧行
  每行 per-turn monotonic sequence
  大正文进 artifacts；事件行留摘要与指针
  AFTER INSERT → pg_notify('turn_events_channel', turn_id::text)
    分发通道另一条：turn_dispatch_channel 的 payload 是 run_id
    ◆ 要点  两路门铃 UUID 含义不同。把 token / 工具结果塞进 NOTIFY 会打满 payload 上限，且丢失不可恢复。

BufferedEventWriter（默认窗 0.04s = 40ms）
  只合并四类高频 delta：turn.token · turn.thinking.delta · tool.delta · section.draft.delta
  刷新后第一条立即 INSERT（首 token 延迟与逐条写入相同）
  窗内后续多行一批；任意非 delta 会先刷缓冲，再走单条事务
  刷盘仍持 pg_advisory_xact_lock(turn_id) + MAX(sequence)+1
    跨进程（孤儿 finalizer、HA 重启）不会抢号
  EVENT_BATCH_WINDOW_SECONDS=0 可回滚到逐条（旋钮，不是第二种语义）
  ◆ 要点  锁的是这个 Turn 的号，不是整张 turn_events。旧路径每个 token 约 4 次 DB 往返。

thinking.delta 与租约/stall 的耦合
  产品 Turn：delta 入 turn_events（SSE live），默认不进 turn_views
  Ops 评测：ops_eval_persist_thinking=False → 不 INSERT delta，改 JSONL sidecar
    同时 ops_eval_thinking_heartbeat_seconds=15，否则 180s stall 会把活评测当死
  非 delta 事件仍立即落库，供 watchdog 看见「还在动」

读出路径（api）

进程启动一根独立 asyncpg.connect LISTEN turn_events_channel
  不从热连接池借（热池 5×5s，LISTEN 会占死槽）
  收到 turn_id → 内存 fan-out：对该 Turn 的等待者 asyncio.Event.set()
  同时入投影队列 → UPSERT turn_views（无 thinking.delta）
  ◆ 要点  一根 LISTEN 叫醒 N 路 SSE。每浏览器一根 PG 套接字会先打满连接，而不是先打满 inflight。

SSE  GET /turns/{id}/stream
  SELECT WHERE sequence > cursor；data = 契约信封 JSON，不是供应商原始 HTTP 字节
  游标三处共用：SSE id · Last-Event-ID · since_sequence · 快照
  空闲 2s poll（反熵：NOTIFY 丢了也能追上）
  ~14s 注释行 : ping；45s 无字节视为闷流，带 since_sequence 重连（≤8）
  终态或 approval.requested 关流（审批后由命令面续，不靠这条长 GET 挂着执行）
  ◆ 要点  SSE ⊈ inflight。挂看不占执行槽；组窗 RAM 是 Turn 级的。

GET /view
  列表 / 首屏 / 重连 / 终态；可 ETag/304
  UI 不推断阶段：阶段只来自已持久化的事件类型
  快照含推理增量 → 列表与审批 UI 被 delta 撑满

信封（契约，SSE data 与行存储同一份）

packages/contracts/schemas/events/envelope.json
  required: event_id · stream_id · sequence · type · turn_id · run_id · ts · payload
  additionalProperties: false；sequence ≥ 1；stream_id 通常 = turn_id
  type 枚举见 types.json（phase0 开工/工具/终态；phase1 流式/审批/补丁；phase2 用量/检索/组窗）

payload 上限（打破则校验红）
  turn.token / thinking.delta / section.draft.delta    delta ≤8192
  tool.completed.summary / turn.completed.summary      ≤4096
  turn.accepted.user_input_preview                     ≤256
◆ 要点  客户端 JSON.parse 的是信封。按供应商 SSE 原始帧去续传，游标对不上 sequence。

无分布式事务时如何自洽

runtime 写  事件、执行态、checkpoint、transcript 真源（编排；不持 ST 权重）
api 写      快照、对外 SSE、常异步的 sessions.context_summary；可 enqueue Redis 索引
短暂落后    以 turn_events.sequence 为序 reconcile；禁止用「api 内存里最新 token」回写 runtime
schema      event_payload_validation 默认开；高频 delta 默认轻量校验（R3），CI 可开 strict
tool.completed summary 最大 4096 字（OpenAPI maxLength）；delegate 大摘要必须 clamp
◆ 要点  没有 XA。领域表（turns.status）可以晚于事件。读 UI 以事件序为准，不要以 turns 行推断「正在想」。
