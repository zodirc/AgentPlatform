# 写作模块：二次审查与执行方案

目标是让系统更有机会写出一部有吸引力、结构连贯、语言可信、AI 味较淡的小说。

先给结论：

> 上一版方案并不完全自洽。它仍默认现有架构值得保留，只想给 system、voice、signals 和 repair 重新分工。这个前提没有证据。

当前更严重的问题可能不是某条 prompt 写错，而是同一个模型在同一条上下文里同时被要求规划、写作、读评分、避惩罚、追奖励和修补自己。控制越多，正文越容易显出控制痕迹。

修正版先问：**哪些东西应该从正文生成路径里删除？**

---

## 1. 对现状和上一版方案的批判

### 1.1 工程精细不等于对小说有效

当前系统有稳定 system、动态 context、评分、补丁预算和交付门。这能证明流程可控，不能证明小说更好。

目前没有证据说明：

- 完整提示链优于精简提示；
- penalties 减少后，读者更愿意继续读；
- 公版样本会增强而不是覆盖作品声口；
- commitment 变奏会减少 AI 味；
- 岛修后的段落更好，而不只是检测器不再命中；
- `net_signal` 与吸引力有关。

所以任何部件都应通过删减对照重新证明自己，而不是默认保留。

### 1.2 给同一条 prompt 分层，不是真正隔离

上一版提出 system、work contract、turn compass、signals、repair 五层。但如果 Writer 最终仍看到：

- 阶段与章节作用；
- 章段；
- voice；
- commitment；
- fragment；
- obligations；
- penalties、rewards 和 repair hint；

那么只是标题变了，注意力污染没有消失。

真正的分层应使用不同调用和不同上下文，只交换最小结果。

### 1.3 AI 味不能作为一个可直接优化的分数

现有检测能抓碎拍、连接词、设定倾倒、解释性旁白等表征。但没有命中这些规则，不等于像人写，更不等于有吸引力。

AI 味还会来自：

- 每章结构过于工整；
- 每句话都有用途，没有生活余量；
- 连续制造秘密、期限和反转；
- 人物总做出主题上正确的选择；
- 为过配额强制换时序、副线或地点；
- 旁白解释本章已经写出的意义；
- 不同作品共享同一种“有质感”的句法。

继续添加总分或禁词，只会制造新的代理目标。

### 1.4 连贯性不能只靠大纲和上一章结尾

几十章后，人物状态、物件去向、世界规则和旧承诺会超出尾段与章纲。

但现有 `story_state` 又包含 reader ledger、wild cards、swerves 等方向性槽位。全量恢复会把小说写成状态机。

需要一个很小的事实账，而不是剧情控制台。

### 1.5 3000 字下限与“不注水”有真实冲突

材料只够一个动作时，硬要求 3000 字，模型只能重复心理、增加无效对话、解释设定或临时制造冲突。

所以顺序必须是：

1. 先检查场景是否有容量；
2. 材料不足则回到章段或章节作用；
3. 材料足够但正文跳写，才扩展同一场；
4. 最后检查字数。

3000 字是产品规格，不是质量指标。

### 1.6 三层章节规划也可能成为模板

“世界入口—阶段推进—章节作用—当前章段”适合很多长篇，不适合所有小说。

它可能让每章都完成明确变化、建立明显依赖、形成整齐阶段。生活流、群像、单元剧和发现式写作可能因此失真。

三层结构应是长篇的默认混合规划方式，不是小说定义。

### 1.7 岛修的工程优点不等于审美有效

仓库没有名为 `repair_patch` 的工具。所谓岛修实际是：

```text
draft_section
→ score_writing_fragment
→ repair_span
→ propose_patch / 自动 apply_patch
→ 整章重评
```

span、预算、唯一性、历史快照都设计得不错。但同一个检测器负责定罪和验收，会形成封闭自证：把短句改成长句后，碎拍消失，不代表段落更好。

岛修应保留工程边界，缩小文学权限。

## 2. 根本结构问题

### 2.1 Writer 同时扮演作者、编辑和质检员

Writer 知道哪些特征会扣分、奖励、触发修复或阻止交付，就会主动：

- 避开检测器；
- 制造奖励证据；
- 改结构以过 commitment；
- 把编辑术语写进旁白；
- 优先完成流程而不是完成小说。

这是系统自己制造的 AI 味。

### 2.2 规划语言泄漏进正文

“人物选择、关系变化、台阶可见、代价到账、世界层露头”适合编辑讨论，不适合反复贴在 Writer 面前。

它们容易变成主题总结、章末升华和显眼钩子。Planner 应把计划转换为事实，不能把抽象术语原样交给 Writer。

### 2.3 `literary / web_serial` 二分过粗

文学小说也可以快，网文也可以克制。同一本书的不同章节也会变化。

当前二分容易把：

- literary 绑定到公版作家句法；
- web serial 绑定到台阶、代价和强钩子。

这不是适配，而是两套大模板。

### 2.4 系统优化的是“容易检测”，不是“真正重要”

容易检测的是字数、短句、连接词、机构开头。真正重要但难检测的是：

- 人物选择是否可信；
- 本章是否非写不可；
- 对话是否改变关系；
- 后章是否由前章造成；
- 世界规则是否长期一致；
- 作品是否有自己的语言身份。

如果检测难度决定修稿优先级，系统会修次要问题，放过主要问题。

### 2.5 自动审美修复会抹平有意的不规则

故意短促的对白、机构名开场、必要的历史叙述、不完整过渡和重复停顿，都可能与 detector 特征重叠。

自动修复倾向把它们改成稳妥、顺滑、可解释的中间文本；这种文本往往更像 AI。

## 3. 修正版目标

系统不能保证写出好小说。它能做到的是：

- 不用过多规则妨碍模型；
- 给 Writer 足够而不过量的作品事实；
- 维持长篇事实连续性；
- 隔离规划、写作和编辑；
- 只自动修复高置信机械问题；
- 把审美决定留给独立审读和用户。

验收拆成四项。

### 连贯

- 后一章依赖前一章已经发生的变化；
- 人物、关系、物件和规则不无故复位；
- 长期信息能回到原文章节；
- 相邻章节不复述，也不机械续接末句。

### 不空泛

- 新信息改变人物当下做法；
- 世界信息通过影响进入，不靠百科解释；
- 对话产生信息、决定、误解或关系变化；
- 章末问题来自本章发生过的事；
- 3000 字不靠重复心理和无关场次补足。

### 语言身份

- 同一本书不同章节能被认出；
- 措辞服从人物、时代和叙述距离；
- 不反复使用通用总结、对称和升华句架；
- 用户认可的本书原文比平台 voice 权重更高。

### 结构

- 大纲记录因果依赖，不只是事件顺序；
- 阶段变化能在正文找到事实；
- 章节作用可以修订；
- 远处保持弹性，近处才具体；
- 规划强度适合作品，而不是适合系统表格。

## 4. 新架构：真正隔离角色

```text
作品状态 → Planner → 事实化写作包 → Writer → 草稿
                                           ↓
                                 独立 Editor（可选）
                                           ↓
                                  用户决定是否修改
```

工具层负责保存、格式、版本和明确规格，不向 Writer 教审美。

### 4.1 Planner

Planner 可以看：

- 整书简介与世界入口；
- 阶段推进；
- 事实账；
- 相关旧章；
- 近处章节作用；
- 用户要求。

Planner 输出写作包：

- 当前人物和地点；
- 已成立的相关事实；
- 本章主要面对的一件事；
- 少量会互相作用的事实；
- 不可违反的世界规则；
- 与上一章的必要连接；
- 用户明确要求。

Planner 不把这些交给 Writer：

- “章节作用”之类的抽象总结；
- reward、penalty、fragment；
- commitment 槽位；
- repair 规则；
- “AI 味”写作课。

### 4.2 Writer

Writer 只看：

- 写作包；
- 当前作品 voice；
- 少量用户认可的本书原文；
- 必要旧章片段；
- 字数和格式；
- 用户消息。

Writer 不看在线评分和修复预算。它的 system 只要求保持事实、完成用户任务、真实落盘，不解释计划。

### 4.3 Editor

Editor 使用新的隔离调用。即使使用同一基础模型，也不继承 Writer 的完整上下文。

它只输出一到三个高价值问题，并给出原文证据，区分：

- 机械错误；
- 局部语言问题；
- 连续性问题；
- 结构问题；
- 用户偏好。

Editor 默认不改正文。用户要求修改，或问题属于机械错误时，才进入修复。

### 4.4 Tool orchestrator

工具只负责：

- 文件与 section；
- 版本历史；
- 字数与格式；
- patch 唯一性；
- 用户授权；
- 交付状态。

工具不定义什么是文学、有吸引力或像人写。

## 5. 作品状态

只保留四类状态。

### Manuscript

正文是最终事实来源。

### Outline

记录可修改的阶段和近处安排，不冒充已发生事实。

### Canon facts

只记正文已经成立的内容：

- 人物当前状态；
- 关系变化；
- 物件去向；
- 已确认世界规则；
- 未兑现承诺；
- 每章持久变化；
- 来源章节和短证据。

不记录 reader tired_of、wild cards、swerves、AI 默认组合或下一章动作。

每章后提取候选事实。与旧事实冲突时不自动覆盖，而是回读原文或进入 Editor。

### Taste / voice

只保存：

- 用户认可片段；
- 用户指出“太 AI / 不像这本书”的片段与原因；
- 简短声口说明；
- 格式约定。

长篇连续性依赖“事实定位 + 原文窗口”，不是依赖越来越长的摘要。

---

## 6. 规划方式

作品建立时选择规划强度，之后可改。

### Planned

适合强情节连载、谜案和升级叙事。保留世界入口、阶段、近处章节作用和当前章段。

### Discovery

适合生活流、人物驱动和实验性写作。只保留当前状态、事实、眼前事情以及作者的疑心和悬置。写完后再回写阶段。

### Hybrid

长篇默认：

- 远处有阶段方向；
- 近处一到三章有作用；
- 当前章有具体事实；
- 正文可以改变计划；
- 写完后以正文更新 outline。

规划模式不由 `literary / web_serial` 自动决定。

---

## 7. voice

### 7.1 默认 voice 极简

没有作品声口时，只给：

- 现代白话；
- 服从人物、时代和叙述距离；
- 对话使用「」；
- 正文不写 Markdown 章标题；
- 不解释计划。

不自动轮转鲁迅、老舍、萧红等公版样本。

### 7.2 样本优先级

1. 用户认可的本书原文；
2. 本书已定稿片段；
3. 用户主动提供的参考；
4. 用户主动选择的公版样本；
5. 通用 voice 描述。

`exemplar_alignment_high` 不作为平台奖励。样本用于校准，不用于得分。

### 7.3 去 AI 不靠禁词表

用户标记某段“太 AI”时，保存原文、原因和适用范围，并与认可片段成对提供。不要积累无限禁词。

`literary / web_serial` 可暂时保留为产品标签，但不能全面决定钩子、台阶、句法、一章几场和人物表达。

---

## 8. signals 与 commitment

### 8.1 生产路径只保留可验证事实

可以影响工具行为的信号：

- 是否落盘；
- 是否达到用户明确字数；
- section 是否正确；
- patch 是否唯一命中；
- 格式是否破坏；
- 是否与 canon fact 明确冲突；
- 是否越权覆盖。

### 8.2 风格信号默认只做遥测

这些默认不回灌 Writer、不挡交付：

- `staccato_uniform`；
- `hinge_dense`；
- `opening_institution`；
- `lore_dump`；
- `meta_knowing_high`；
- `glue_heavy`；
- `fragment_mismatch`；
- 所有 exemplar / plot step / price / world layer rewards。

它们进入日志、Editor 候选证据和离线评测。只有人工验证为高精度、局部可修的信号，才升级为修稿建议。

### 8.3 不保留生产总质量分

`net_signal` 暂时可保留兼容，但：

- Writer 不可见；
- 不控制交付；
- 不决定 patch；
- 不宣称代表质量；
- 后续迁移为 telemetry。

结构、吸引力和语言不合成一个数。

### 8.4 commitment 退出硬门

取消默认组合次数、时序连用限制和“改一个槽位再交”。如需研究章节形状，落盘后离线提取，不在写前强制声明。

fragment 也只作分析标签，不生成正文义务。标签推断错了，不能让正文负责。

## 9. repair

### 9.1 三类问题

**机械问题，可自动修**

- 重复段落；
- 破损引号；
- 错误标题格式；
- 工具写入造成的重复；
- 明确定位错误。

**局部风格风险，只建议**

- 碎拍；
- 连接词密集；
- 解释性总结；
- 设定段过重；
- 对称金句；
- 模板化章末。

Editor 给证据和候选 patch，用户或隔离的 Writer 决定。

**结构问题，禁止岛修**

- 章节没有作用；
- 人物选择不可信；
- 世界进入突兀；
- 章节顺序无因果；
- 一章靠注水达到 3000；
- 本章不属于这本书。

返回改纲、重写或保留，不能用三次小补丁掩盖。

### 9.2 保留岛的工程边界

保留 `repair_span`、唯一命中、岛未触及拒绝、patch 预算、history 和小范围 diff。

改变：

- 审美 patch 不自动 apply；
- 同一 detector 不能独自证明“变好”；
- 验收只说风险是否减少；
- 用户认可原句可以豁免；
- Writer 不看完整 repair playbook。

`length_short` 不是局部岛。低于 3000 时先检查容量，材料不足回 Planner，材料足够才重写同一场。

---

## 10. system.md 应该剩下什么

稳定 system 只保留：

- 身份、用户授权和 workspace 真实性；
- 选书、规划、写作、编辑的任务边界；
- 当前作品事实和用户确认 voice 优先；
- 工具落盘与诚实交付。

移出：

- 小说定义和三要素；
- 一章一场、池子和海；
- 章职形状；
- 文学/网文写法；
- staccato 修法；
- rewards、penalties、commitment；
- 具体数字和 patch 预算。

甚至“小说是人物在处境里做选择”也不应作为所有作品的系统真理。它适合许多叙事小说，不覆盖全部类型。

## 11. 是否符合预期

### 章节连贯

依靠小型事实账、相关原文检索、上一章片段、阶段与近处作用，以及写后事实抽取。不能只靠“承接上文”的提示。

### 不空泛

主要在生成前解决：章段有互相作用的事实，场景容量足够，世界信息有现实影响，Writer 不看抽象规划术语。

detector 只能抓症状，不能从空泛文本修出扎实内容。

### 措辞少 AI 味

不能保证，只能提高概率：

- 减少平台通用口号；
- 移除评分词和修稿教程；
- 不强制结构变奏；
- 使用本书认可原文；
- 正负例成对；
- Writer 与 Editor 隔离；
- 不自动抹平有意的不规则。

基础模型本身的总结、对称和解释倾向，仍需样本、重写和人工选择。

### 大纲有逻辑

检查：

- 后一事件是否需要前一事件；
- 人物为何此时这样做；
- 世界规则是否允许；
- 关系变化是否有积累；
- 阶段终点是否有正文事实；
- 交换两章后是否仍成立。

这些由 Planner 和 Editor 检查，不变成 Writer 的口号。

没有证据的部件默认关闭。`legacy` 保留旧控制链，默认不走它。

- `writing/cards.py`

- `controller/input_compiler.py`

每条事实带来源，冲突不自动覆盖。

修改：

### 阶段 7：统一长度

修改 `writing/text_metrics.py`、`writing/book_scope.py`、`tools/bootstrap.py` 和 `writing/delivery_gate.py`。

默认 3000—5000 个可见字符；用户要求优先；低于 3000 先检查容量，不直接 append 第二场。

### 阶段 8：独立 Editor

复用 editor / reread，但用隔离调用。只提一到三个问题，引用原文，不默认改稿。

## 13. 方案自身的风险

- Writer 看得更少，可能漏掉伏笔；允许主动回读，并记录检索遗漏。
- Planner 可能成为新模板；Discovery 模式必须能绕过章节作用。
- canon extractor 会把推测当事实；原文始终优先，重要事实带证据。
- 同一基础模型的 Editor 仍可能有相同偏见；改不改由用户决定。
- 移除 signals 可能放回坏习惯；通过 feature flag 和遥测灰度，不一次永久删除。
- Planner、Writer、Editor 增加成本；Planner 按需，Editor 按需或阶段触发。
- 3000 字只作为当前产品默认；短章、间章和故意截断需要例外。
