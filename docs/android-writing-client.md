| 项 | 内容 |
|----|------|
| 状态 | 草案，未开工。须在第一部分的宿主协议 1.0 冻结、且第 13 节门禁通过后才开始开发 |

## 1. 目标与非目标

**目标**

1. 用户安装后只需选择服务商、填入 key，即可开始写作。
2. 写作行为完全由第一部分的内核包提供，本仓库不含任何写作规则。
3. 稿子可完整导出，不因卸载、换机或回合中断而丢失。
4. 每回合的花费在开始前可预期，进行中可见、可中止。
5. 写作内核可以单独更新（受渠道政策限制，见第 8 节）；安装包更新尽量走差分。

**非目标**

- 不追求与服务器写作逐字等价（差异见第一部分第 9 节，须在"关于"页说明）。
- 不做账号、云同步、多设备协同；手机上不做 embedding、资料库或子 Agent。

## 2. 与第一部分的边界

| 本仓库负责 | 第一部分负责 |
|------------|--------------|
| 界面、密钥、前台服务、文件导入导出 | 写作规则、回合组装、引擎、组窗、工具 |
| 内核包的下载、校验、槽位切换与回滚 | 内核包的构建、签名、清单 |
| 服务商预设数据 | `probe_model` 探测逻辑 |
| 预算设置与用量展示 | 用量统计与预算执行 |
| 原生依赖（Chaquopy 中的 pydantic、httpx 等） | 依赖白名单与 `host_requires` 声明 |

两部分只通过宿主协议交互。本仓库只调用协议入口，不导入内核的内部模块。需要内核新增能力时，先在第一部分提出协议变更。

## 3. 仓库

### 3.1 决策

采用独立仓库。理由：

- 工具链不同（Gradle、JDK 17、Android SDK），与 runtime 的 Python CI 互不干扰。
- 发布节奏、签名密钥、渠道配置只属于客户端。
- 内核以版本化产物的形式消费，强制两部分只经由协议耦合。

代价：内核变更需要单独提一个"升级内核版本"的 PR 才能进入客户端；跨两个仓库排查问题会慢一些。前者是有意为之。后者靠第 3.3 节的回放夹具缓解。

**建仓时机**：等宿主协议 1.0 冻结之后。协议还在变的时候，在本仓库的 `clients/android/` 下做原型（第 13 节），门禁通过后再迁出。

### 3.2 布局

```text
writing-android/
  app/                      # Compose 界面、导航、ViewModel
  host/                     # Chaquopy 集成、内核加载器、协议的 Kotlin 绑定
  update/                   # 更新检查、APK 差分合成、内核槽位
  presets/                  # 服务商预设（JSON 加 schema）
  core.lock                 # 内核版本、sha256、签名公钥指纹
  build-logic/              # 渠道与签名配置
  fixtures/                 # 随内核包发布的回放夹具
```

### 3.3 内核接入

1. `core.lock` 写明内核版本与 sha256。
2. Gradle 任务从第一部分的发布产物中拉取 `writing-core-<ver>.zip`，校验签名与哈希，放入 assets 作为**内置内核**。
3. 升级内核即修改 `core.lock` 并提 PR。CI 在模拟器上用内核包附带的回放夹具跑一回合，通过后才能合入。

## 4. 架构

```text
┌──────────────────────── Android 应用 ────────────────────────┐
│ Kotlin                                                       │
│   app/      作品 · 稿 · 回合 · 设置                           │
│   update/   APK 差分 · 内核槽位 · 预设                        │
│   host/     内核加载器 → 选槽位 → 校验 → sys.path              │
│ Chaquopy（CPython 3.11 加原生依赖）                           │
│   内核：内置 | 槽位 A | 槽位 B（三者取其一）                   │
│   宿主协议：start_turn / resume_turn / cancel_turn / probe     │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTPS：用户的模型服务
                               │ HTTPS：更新清单（静态文件，可关闭）
```

- Python 运行在一条后台线程的 asyncio 循环中。协议的 `on_event` 回调切回主线程更新界面。
- 内核加载器在导入内核前，把选中的槽位目录插到 `sys.path` 最前面。原生依赖始终来自 APK。

## 5. 模型接入

### 5.1 服务商预设

设置页先选服务商，再填 key。预设随 APK 内置，也可单独更新（第 8.4 节）。

| 字段 | 用途 |
|------|------|
| 根地址 | `chat/completions` 端点 |
| 推荐模型与可选模型 | 下拉选择 |
| 上下文窗口 | 填入 `ModelConfig.context_window_tokens` |
| 能力 | 是否支持流式 tool_call、并行工具 |
| 计价（可选） | 费用估算；缺失时只显示 token |

另设"自定义 OpenAI 兼容"项，要求用户手填窗口大小。

### 5.2 探测

保存配置时调用 `probe_model`，逐项展示结果。任一项失败都不允许开始回合。

### 5.3 预算与用量

| 机制 | 说明 |
|------|------|
| 回合预算 | 设置中可调的 token 上限，作为 `TurnBudget` 传入；触顶时内核走收尾路径 |
| 实时用量 | 回合页按 `usage` / `step_committed` 事件显示累计 token 与估算费用 |
| 累计统计 | 按日、按作品统计 |
| 中止 | 调用 `cancel_turn`；已提交的稿保留 |

## 6. 稿与数据

| 要求 | 做法 |
|------|------|
| 多作品 | 每个作品一个目录 `works/<id>/`，内部布局见第一部分第 6 节 |
| 不因卸载丢稿 | 整作品导出 / 导入为 zip，经 SAF 选择位置；首个回合完成后引导用户设置导出位置 |
| 不依赖系统备份 | 系统备份只作补充（有容量上限，且部分 ROM 不提供） |
| 密钥不进备份 | 密文从备份规则中排除；恢复后检测到无法解密时，引导用户重新填写 |
| 可回退 | 每回合开始前保存受影响章节的快照；稿页提供"撤销本回合"和按回合的版本列表 |
| 编辑冲突 | 回合进行中稿页只读；用户的手动编辑在回合之间进行 |
| 清理 | 设置中可清理旧断点、事件与归档稿 |

## 7. 回合生命周期

| 项 | 设计 |
|----|------|
| 承载 | 前台服务；类型按 targetSdk 的要求声明。须核实所选类型在 Android 14/15 上的时长限制，并准备上架审核所需的用途说明 |
| 提交 | 界面只在收到 `step_committed` 后刷新稿 |
| 恢复 | 启动时调用 `list_resumable`，询问用户是否继续。被打断的那一步要重新请求模型，会产生额外花费，恢复前须提示 |
| 网络 | 断网时在步边界暂停，网络恢复后由用户确认继续 |
| 取消 | `cancel_turn`，在步边界生效，当前流立即中止 |
| 通知 | 完成、失败、预算触顶各一条 |
| 与更新互斥 | 有回合进行中或待恢复的回合时，不切换内核槽位、不安装 APK |

## 8. 更新

### 8.1 分层

更新拆成三层，变化越频繁的层越轻：

| 层 | 内容 | 频率 | 典型体积 | 方式 |
|----|------|------|----------|------|
| 预设 | 服务商预设 JSON | 高 | KB 级 | 签名数据文件，全渠道 |
| 内核 | 写作内核包（纯 Python） | 中高 | MB 级（以实测为准） | 签名包，整包下载，A/B 槽位 |
| 安装包 | 壳、CPython、原生依赖、内置内核 | 低 | 数十 MB 级（以实测为准） | 按渠道；侧载渠道走差分 |

写作行为的迭代绝大多数只涉及内核层，在允许内核热更新的渠道里无需发 APK。

### 8.2 渠道

| 渠道（flavor） | 安装包更新 | 内核热更新 | 预设更新 |
|----------------|------------|------------|----------|
| `play` | 只走 Google Play（Play 自动差分；应用内用 In-App Updates 提示） | **关闭**。Play 政策限制应用从 Play 以外下载可执行代码，解释型代码的豁免边界不清，不冒险 | 开启 |
| `store`（国内商店） | 交给各商店（多数自带增量更新） | 默认关闭；逐家核对商店政策后按渠道开启 | 开启 |
| `direct`（官网侧载） | 自建，差分优先（第 8.3 节） | 开启 | 开启 |

`play` 渠道不含 `REQUEST_INSTALL_PACKAGES` 权限和自更新代码，构建时直接排除 `update/apk` 模块。

### 8.3 安装包差分（`direct` 渠道）

1. 读取更新清单，比较 `versionCode`。
2. 用已安装包的 `ApplicationInfo.sourceDir`（base.apk）计算 sha256，在清单中查找"从该哈希到新版本"的补丁。
3. 有补丁就下载补丁，用 HDiffPatch 在本地合成新 APK；没有补丁或合成失败，就下载整包。
4. 校验合成结果的整包 sha256，必须与清单一致。
5. 用 `PackageInstaller` 会话安装。系统会校验签名证书与已安装版本一致；首次使用需要用户授权"安装未知应用"。

发布侧：每个新版本针对最近 K 个已发布版本各生成一个补丁，更早的版本只能下载整包。签名密钥不得更换，一旦更换，差分与覆盖安装都会失效。

### 8.4 内核热更新

**兼容条件**（任何一项不满足就跳过该内核，必要时提示先更新 APK）：

- 签名与文件哈希校验通过。
- `protocol_version` 主版本在壳支持的范围内。
- `python` 版本与 APK 内的解释器一致。
- `host_requires` 中的原生依赖与版本都由当前 APK 满足。

**槽位与切换**

```text
files/core/
  slot-a/   slot-b/   state.json   # active、pending、上一个可用版本、启动失败计数
```

1. 下载到非活动槽位并校验，标记为 `pending`。
2. 下次冷启动时，若没有进行中或待恢复的回合，就加载 `pending` 内核并执行自检：导入协议入口，读取 `core_info`，读取一个最小回放夹具的断点。
3. 自检通过则标为 `active`；失败则回到原槽位。
4. 切换后的前若干次启动中，若内核加载阶段崩溃次数达到阈值，自动回滚到上一个可用槽位；所有槽位都不可用时，回到 APK 内置内核。

**选择规则**：在内置内核和两个槽位中，选兼容且版本最高的那个。APK 更新后，如果内置内核比槽位里的更新，以内置为准。

**数据兼容**：内核只做向前迁移（第一部分第 6 节）。回滚后，若遇到由更新内核写下的断点，返回 `ResumeIncompatible`。此时提示用户"该回合无法继续"，已提交的稿不受影响。

### 8.5 更新服务

- 只托管静态文件（对象存储或 CDN）：`<channel>/manifest.json` 及其签名，内容包括 APK 版本、整包与补丁、内核包、预设。
- 请求只是 GET，不携带设备标识、作品信息或 key。
- 这是除模型服务外唯一的出站地址，须在隐私说明中列出。设置中可选"自动检查""仅手动检查"或"关闭"。
- 清单签名公钥内置在 APK 中，与内核签名使用不同的密钥。

## 9. 安全

| 项 | 设计 |
|----|------|
| API key | 用 Keystore 生成的 AES-GCM 密钥加密，密文存 DataStore。不采用已弃用的 EncryptedSharedPreferences |
| key 去向 | 只发往用户配置的模型地址 |
| 明文 HTTP | 默认禁止；仅对用户显式标为"局域网"的地址放行 |
| 日志 | 写入前脱敏 key 与 Authorization 头；诊断日志导出同样脱敏 |
| 代码来源 | 只加载内置内核，或签名校验通过的槽位内核 |

## 12. 技术选型

| 层 | 选择 |
|----|------|
| 解释器 | Chaquopy，CPython 主版本与内核清单一致（当前 3.11） |
| 界面 | Kotlin、Jetpack Compose、Navigation |
| 系统版本 | minSdk 取 Chaquopy 要求与 26 中较高者；targetSdk 跟随商店当年要求，写死在构建脚本中 |
| 配置 | DataStore |
| 密钥 | Android Keystore（AES-GCM） |
| 网络 | 模型流由内核内的 httpx 负责；若门禁 G3 失败，改为 OkHttp 加协议级传输回调 |
| 差分 | HDiffPatch（`direct` 渠道） |
| ABI | 仅 `arm64-v8a` |
| 构建 | Gradle Kotlin DSL，JDK 17；CI 用 cmdline-tools 无头构建 |

## 13. 开工门禁

前提：第一部分已完成验收。原型在 `clients/android/` 中完成，不在新仓库里做。

| 编号 | 验证项 | 通过标准 |
|------|--------|----------|
| G1 | 原生依赖 | 内核清单中 `host_requires` 的每个包在 Chaquopy 上都有可用 wheel |
| G2 | 回放一致 | 用内核包附带的回放夹具在真机上跑一回合，结果与桌面命令行宿主一致 |
| G3 | 真实长流 | 用至少两家服务商完成 40 步真实回合，无流中断 |
| G4 | 断点恢复 | 回合中途杀进程后恢复正确，无重复补丁 |
| G5 | 内核热切换 | 槽位切换、自检失败回滚、崩溃回滚三条路径在真机上走通 |
| G6 | 差分安装 | 侧载包从旧版本差分升级，合成哈希一致且安装成功 |
| G7 | 基线 | 记录 APK 大小、内核包大小、冷启动耗时、回合期间内存峰值 |

## 14. 风险

| 风险 | 影响 | 处置 |
|------|------|------|
| 用户选用工具调用能力弱的模型 | 回合质量差，被归咎于应用 | 预设、探测、推荐模型标注 |
| 花费超预期 | 流失、差评 | 回合预算、实时用量、开始前提示 |
| 稿丢失 | 不可接受 | 导出 / 导入、回合快照、首回合后引导设置导出 |
| 坏内核推送到用户 | 无法写作 | 签名、兼容检查、自检、崩溃回滚、内置内核兜底；发布时先小比例灰度 |
| 签名密钥泄露或丢失 | 恶意更新，或再也无法覆盖安装 | APK、清单、内核三把密钥分离，离线保管并备份 |
| 渠道政策变化 | 下架 | 内核热更新按渠道开关；`play` 渠道不含自更新 |
| 前台服务被厂商策略终止 | 回合中断 | 步级断点与恢复；主流 ROM 的保活设置引导 |
| 上架合规（国内应用备案、生成式 AI 相关审核） | 无法上架 | 首版只出 `direct`；上架前单独评估用户自带 key 形态下的合规要求 |
