# 大纲优化：实际执行方案

依据 [writing-outline-optimization-plan.md](writing-outline-optimization-plan.md) 与现行实现 [writing-outline.md](writing-outline.md)。本文只确定实施边界、依赖关系和验收方式，不在这一步改代码。

## 结论

上一版执行稿不能直接实施，主要问题如下：

1. 立意门放进 `excerpt_job.py`，层级错误。`excerpt_job` 检查候选成文表面，不能判断“人的牵引力”和“类型的改造力”；live 候选也先在 `candidate_sample.py` 完成，再进入该闸。
2. 当前候选提示明确要求“不写到某一个人和某一件事”，与新的立意要求正面冲突。只追加几句“人物愿望”不会生效。
3. `subject_pool.py` 仍会向宽泛都市题材注入对象级参照。若不一起处理，模型仍会产出“现代设施 + 超自然名词”的嫁接。
4. 分出章文件后，`has_chapter_jobs`、相位、spec 和 signals 仍只读传入的 `outline` 字符串。把这些改动推迟到最后，会使新文件写得出、开不了章。
5. 执行稿使用了卷文件，却没有安排创建、读写和兼容卷文件的切片。
6. `canon.py` 已在 `draft_section` 后运行，但当前正则只能可靠确认少量人物、物件和规则；关系、承诺、变化默认仍是 clue。它不能直接提供“上一章不可撤销结果”。
7. “总结和心理活动”的问题发生在正文中，只检查 `update_outline` 的 summary 无法解决。
8. 多文件写入后仍把新路径塞进事件 summary，会让事件消费者无法可靠知道哪些文件改变。

因此，实际顺序必须先建立评测基线和统一读写层，再迁移文件；正文检查与大纲检查分开。

## 已确定的取舍

1. 不把立意门做成禁词或正则表。
2. 不新建第二套事实库。继续使用 `.agent/work/canon_facts.json` 和生成的 `confirmed.md`，但补足可验证的章结果。
3. 暂不新建 `voice.md`。本书声口继续使用现有 style card、author state 和 taste；声口样本另立后续项目。
4. 保留 `update_outline` 工具名，增加分层写入合同；旧的 `content + mode` 调用继续兼容。
5. 八十字门暂时只作为“内容存在”的下限，不能再被文档或测试解释成质量证明。没有替代门之前不删除。
6. 沿用 `discovery` / `hybrid` / `planned`。规划强度只控制前瞻范围，不决定是否能看到当前卷问题。
7. 《回水巷》只作为失败夹具：它应在题材成立性阶段被退回，不能用作合格 golden。

## 文件目标

```text
outline.md                   # 作品级：核心处境、叙事承诺、主要力量、长程边界
volumes/
  volume-001.md              # 卷问题、阶段变化、尚未决定
chapters/
  ch-001.md                  # 当前章便条
confirmed.md                 # 从 canon_facts.json 发布的已确认事实，只读产物
.agent/work/canon_facts.json # 正文事实与经证据确认的章结果
```

旧 Work 的单文件 `outline.md` 必须继续可读。迁移只在用户或模型下一次明确更新某层大纲时发生，不启动全库自动重写。

## 实施切片

每一刀可单独合入。下一刀开始前，上一刀的单测和选定评测集必须通过。

### E0 建立评测基线

提示词改动之前先建立固定输入集，否则无法区分“更复杂”与“更好”。

输入集至少覆盖：

- 只给宽泛题材；
- 明确点名人物愿望；
- 两个领域的名词嫁接；
- 先写设施或冷门职业、人物缺席；
- 人物成立但类型只是包装；
- 人物成立且类型改变成功含义；
- 用户主动要求传统套路或明确参考作品；
- “我要其他的”及旧候选排除。

评测分两层：

1. 基础成立性：是否有人物牵引、题材是否参与核心因果、是否存在持续发动机。
2. 口味：用户是否想看。

第一层才允许进入自动门；第二层仍由用户点选，不让模型代替用户决定。

《回水巷》进入“题材名词嫁接”失败组。测试理由不是出现“管网”，而是修真仅替换能源介质，城市和人物关系不因修真而改变。

### E1 重做候选形成与立意门

#### E1a 改候选生成合同

当前 `_FORM_SYSTEM` 要求只写世界、年代和力量，不写人物与事件。应整体替换，不在末尾追加补丁。

候选不是两次直出。每次请求先用一个有界响应同时铺开四个临时短方向，使模型必须看见方向之间是否只是同义换皮；短方向只说明核心想象、世界尺度、人物位置和长篇去向，不设计第一卷事件。四个方向随后分别用只看本方向的全新 messages 生成 `title + pitch`，终审只看成文结果并选择至多两个。

这一步把“思考”外显为有界搜索，不开启可能长时间空转的内部 thinking，也不要求每个方向填写创作理论栏目。宽泛题材先兑现读者通常理解的类型承诺，不能为了显得新奇，把城市职业、设施、行政登记和合同整体改名成超自然系统。终审不得为了凑数放宽；若首轮不足两本，只再做一次不参考旧卡的独立搜索。UI 只收到通过终审的书名和简介。

`pitch` 是商业网文书页级的泛化简介，不是大纲。可以偏核心想象、世界气质、人物位置或宽阔去向，不负责证明第一卷因果已经闭合。live schema 用 20–180 字符作输出预算；提示通常写 60–140 个汉字。

硬拒无法改写同一条件下的 token 分布：拒了再采，模型仍容易回到高概率的迷你大纲和“是……还是……”收束。因此成文侧继续用书页级正例把下一 token 拉向简介口吻，并压低输出预算；差异靠方向本身像不同开书卖点拉开，而不是在提示里堆正交轴清单。口吻与过细问题只作为软亲和度排序；终审后若两本骨架过近，再从已成文卡中改挑差异更大的一对。

#### E1b 处理题材参照池

`subject_pool.py` 不能继续把对象级缩影直接注入新合同。先做二选一：

- 第一版关闭宽泛都市题材的随机参照，只按用户原话采样；或
- 把参照改成关系和类型作用层，不提供设施、职业和可换名的情节对象。

在没有评测证明新参照有效前，优先选择关闭，而不是继续维护七十五条旧参照。

#### E1c 独立立意检查

每个候选单独检查，不与另一本比较，也不把拒绝理由送回原文本修补。检查只返回固定原因码：

- `no_human_pull`
- `genre_decorative`
- `noun_graft`
- `moral_pre_solved`
- `no_serial_engine`

语义问题不能放进 `obvious_meta_text` 或 `excerpt_job` 的正则。应在 `candidate_sample.py` 的单槽采样内完成：候选失败后丢弃，使用全新 messages 重采该槽，仍受明确的次数上限约束。

立意检查先以 shadow 运行，记录原因但不丢卡。固定集和人工盲评稳定后，才对高置信原因启用拒绝。格式错误、空字段和撞旧卡仍可立即硬拒。

这里的 shadow 原因码不承担最终选书。实测表明“先选短方向、只把两个方向成文”会让方向阶段的抽象正确性掩盖成文后的公版化，因此增加成文终审。终审既检查职业、姓名和地点整体替换后是否仍是同一本空壳，也检查卡片是否越权写成第一卷梗概：具体案件、连续查证、幕后嫌疑、固定代价和结尾二选一都不属于这一层。终审拒绝整张卡，不生成修补稿。

#### E1d 候选模型路由

实践结果表明，扩大同一 Flash 模型的采样池，再由同一模型筛选，仍可能只是重复同一个低熵分布；提示词和候选池不是独立能力来源。因此增加一个窄路由 `writing / book_candidates`，允许用户从已保存的供应商配置中，为方向搜索、筛选和候选成文共同指定另一模型。

路由为空时继承当前 active 模型；目标配置被删除、缺失或密钥无法解密时也安全回退。显式 Turn 模型覆盖优先于用户路由。shadow gate 保持使用当前模型，不跟随候选路由。这里只提供能力分工，不建立任意阶段矩阵，也不宣称多模型天然能改善审美。

#### E1 完成条件

- 提示合同不再主动要求以设施说明开场或让人物缺席。
- “都市 + 修真”的提示合同不再主动要求城市基础设施的灵气版本。
- 四个短方向在作品身份层显式拉开，随后四张候选分别成文，互相看不到书名和正文。
- 最终选择发生在成文后；质量不足时允许少于两本，并至多启动一轮全新搜索。
- 用户点名具体设定时不会被通用立意门改写。
- 失败候选不会以修补稿进入卡片。
- 候选链可选择独立模型；路由不存在或失效时不阻断采样。

### E2 建立统一的大纲存储层

不能让每个调用方自己判断旧文件或新目录。新增一个统一 store/facade，负责：

- 读取作品级大纲；
- 读取卷纲；
- 读取指定章便条；
- 判断是否存在可开写的当前章便条；
- 生成旧调用方需要的兼容投影；
- 迁移旧 `outline.md` 中的章段；
- 以一次逻辑操作写入多个文件。

#### 写入合同

保留 `update_outline` 名称，新增明确目标，而不是解析任意全文后猜测拆分：

- `scope=work`
- `scope=volume, volume_index=N`
- `scope=chapter, section_id=chN`
- 或一次提交 `documents`，原子写入 work、volume、chapter 三层

旧的 `content + mode` 继续写旧式 `outline.md`，直到该 Work 首次使用新合同。不要把一段混合 Markdown 静默拆到多个文件。

多文件写入先在临时位置完成校验，再整体提交；任一层失败时不能留下半套大纲。

#### 同一刀必须切换的读取方

- `extract_outline_job`
- `extract_chapter_role` 和相邻章作用读取
- `has_chapter_jobs`
- `chapter_job_visible`
- `turn_phase.snapshot`
- `resolve_outline_phase`
- `signals/spec.py`
- `signals/assemble.py`
- `opening_arc` 中读取第一章的逻辑
- `writing_pack.py`

这些读取变化不能推迟到最终相位切片。否则新章文件存在时，`draft_section` 仍会报告没有章纲。

#### 事件合同

`outline.updated` 在这一刀增加向后兼容字段：

```text
changed_files: [{path, scope, section_id?, volume_index?}]
```

原有 `path / content / summary / mode` 暂留，代表主要写入。不能把新文件路径藏在 summary。

#### E2 完成条件

- 旧单文件 Work 不迁移也能继续写。
- 新 Work 可以一次写入作品纲、第一卷和第一章便条。
- 所有相位和写作包通过同一个 store 读计划。
- 另起一篇不会读入旧目录。
- append、replace、灾难性缩短保护在每个目标文件上有明确语义。

### E3 生成分层大纲

E2 只解决存取，E3 才改变点选后的生成内容。

点选作品后，一次规划提交应包含：

1. 短的作品级大纲；
2. 当前卷问题与初始压力；
3. 第一章便条；
4. 最多后一两章的一句依赖。

不强制填满所有栏目。`discovery` 可以只有作品纲、当前阶段问题和第一章；`hybrid` 增加少量卷内依赖；`planned` 可以写关键节点，但仍不生成整卷逐章细纲。

候选简介只作为来源。作品级大纲必须重新提取人物位置、主要矛盾和叙事承诺，不能长期复制 pitch。

### E4 补足已发生事实和章结果

现有 `draft_section` 已调用 `note_chapter_candidate`。本刀不是“接入 canon”，而是补足它无法可靠提供的章结果。

#### 章结果

`draft_section` 可接受少量结构化 outcome：

- 结果文本；
- 对应正文中的短证据；
- 受影响的人、关系、物件或承诺；
- 是否会约束下一章。

工具只接受能在落盘正文中核对到证据的结果。核对失败则不写 canon。章结果写入现有 `canon_facts.json`，使用明确的 confirmed 类别；不要沿用当前会把 `change` 强制降为 clue 的路径。

#### 计划偏差

“正文偏离章便条”不是作品事实，不写进 `confirmed.md`。它只进入本章 tool result 或 manifest 的诊断字段，供下一次规划时决定是否修改章纲。

#### E4 完成条件

- 正文优先于旧计划。
- 上一章关键结果有正文证据。
- 关系、承诺和状态变化不会因为正则没命中就全部消失。
- 未核对的话、人物猜测和作者计划不进入 confirmed。

### E5 分开规划检查与正文检查

所有检查最多返回三条最影响下一步的问题，不打总分。

#### E5a 规划侧，挂在 `update_outline`

- 章便条是否有可展开的行动—回应—调整；
- 四千到五千字容量是否明显过空或过满；
- 前后章是否存在因果依赖；
- 新元素是否有前因；
- 换题材或换主角后，关键步骤是否仍原样成立。

这些先作为软事实。五到八个节拍、二百到六百字都只是观察区间，不进硬门。

#### E5b 正文侧，挂在 `draft_section`

- 总结是否跳过第一次发现、关键选择或关系变化；
- 心理活动是否有现场触发；
- 删除心理解释后是否损失新的判断或动作；
- 是否为补字数临时制造陌生反派、期限、误会或秘密；
- 是否靠重复解释撑到四千字。

正文问题不能依靠禁词表，也不能只检查大纲。已有 L0/L1 信号可承载观测，但新信号先 shadow，不触发同轮自动重写。

#### 八十字门

第一阶段保留 `NEAR_JOB_MIN=80` 作为最低存在门，同时明确：

- `<80`：拒绝开写；
- `>=80`：只表示有便条，不表示便条合格；
- E5a 问题仍返回给模型补纲；
- 没有稳定替代门前不实施“几乎为空才提醒”。

### E6 调整写作包投影

在 E2 和 E4 稳定后修改 `compile_writing_pack_parts`。当前章只拿：

1. 作品级的核心处境与叙事承诺；
2. 当前阶段或卷问题；
3. 与本章人物、地点和线索相关的已确认事实；
4. 上一章经证据确认的关键结果；
5. 当前章便条；
6. 后一章若依赖本章，只给一句；
7. 已有本书声口材料中的少量相关内容。

`discovery` 仍可看到当前阶段问题，只是不读取远处节点。`planned` 可以多带已经写明的关键依赖，不能带整卷目录。

候选 pitch、世界入口全文和远处阶段摘要不再长期注入正文写作包。

### E7 最后处理控制流和界面

前面各刀稳定后再做：

- 工具白名单读取统一 store 的状态；
- `outline_wait` 改为检查当前章便条；
- `outline_awaiting_direction` 保持“规划完成后停”，但依据分层写入结果；
- 工作台展示作品纲、卷纲和章便条；
- 旧事件消费者迁移到 `changed_files`；
- 更新导览和实现文档。

Engine 的 while 和场景识别方式不需要改变。

## 测试要求

### 单元测试

- 候选形成、独立 gate、单槽重采和拒绝次数上限；
- 候选模型路由的 owner 隔离、全候选链生效、Turn 覆盖与安全回退；
- subject pool 关闭或新参照合同；
- 旧纲读取、新纲读取和懒迁移；
- 多文件原子写入与任一文件失败回滚；
- 新旧 `outline.updated` payload；
- 所有相位在 split layout 下与旧 layout 等价；
- outcome 证据核对、confirmed 与 clue 分流；
- 写作包只投影允许的局部信息。

### 质量回归

- 固定题材集盲评候选，不向评审暴露版本；
- 记录“想继续看”的理由，不只记录通过率；
- 对候选执行名词替换、题材移除和人物替换；
- 同一章纲各生成两到三章，检查是否靠解释和临时事故补字；
- 删除心理段，判断是否损失动作或信息；
- 统计关键场面被总结跳过的比例。

质量评测不能写成只匹配固定句子的 golden。测试应固定输入、结构合同、拒绝码和事实证据；文学好坏保留人工盲评。

## 明确不做

- 不把优化方案中的栏目全部变成必填。
- 不把四千到五千字、五到八个节拍或章纲字数写成硬门。
- 不把《回水巷》正文当正例。
- 不让正则承担题材成立性判断。
- 不把计划偏差写成 canon。
- 不在存储读适配完成前把章段移出 `outline.md`。
- 不用 summary 代替多文件事件合同。
- 不因本次大纲改造重写 Engine 主循环。
- 不建立任意场景、任意阶段的模型矩阵。

## 推荐执行顺序

严格按以下顺序：

1. E0 评测基线；
2. E1a 候选合同；
3. E1b 题材参照池；
4. E1c 立意 shadow gate；
5. E2 统一存储、读适配和事件合同；
6. E3 分层大纲生成；
7. E4 可验证章结果；
8. E5a 规划软检查；
9. E5b 正文 shadow 检查；
10. E6 写作包投影；
11. E7 控制流与界面；
12. shadow 数据稳定后，再决定哪些立意或正文问题升级为硬拒。
