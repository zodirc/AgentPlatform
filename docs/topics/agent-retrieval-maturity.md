# Agent 检索成熟方案（分车道 · 门控融合 · 可停环）

> **受众**：检索 / agent 产品负责人、下一轮实现与评审模型  
> **日期戳记**：2026-08-06  
> **性质**：产品路径方案备忘（非评分 hack 清单）。面向真实 `Session → Turn → search_sources` 场景。  
> **上游**：同目录 `retrieval-free-l1-tuning-brief.md`（门禁 / 停机线 / 不做清单以其为准）；`structural-leverage-proposals.md`（结构刀 P1–P4 等）。本文**不推翻**已收裁决。  
> **触发证据**（仅作动机，不写入实现特判）：SciFact 中库微 L1 free（`99fce913` 等）上，cover/keyword 修复后 nDCG@10 ~0.84；残余为「融合截断埋金」「弱名次」「找到后仍续搜」。  
> **总原则**：方案必须在**任意私有 Work 语料**上成立；禁止按数据集 / 题号 / qrels / gold id 分支。

---

## 0. 一句话

成熟形态是：**工作区隔离的分车道召回 → 门控融合（或并集）→ 浅重排 → 带车道/分差信号交 agent → 证据足够则停**。  
相对现状「无条件混融 → 截断 → 模型盲目改写再搜」，问题分别卡在融合截断、名次、停止决策三环。

---

## 1. 真实 agent 检索流程（现状）

```text
用户意图
  → writing（等）自由 Turn
  → search_sources(query, limit≈30, path_prefix?)
  → 向量车道 + 词面/BM25 车道（常默认可见 seed）
  → 融合排序 → 截断 top-K
  →（可选）cover 门 / keyword 回退
  → 结果进上下文
  → 模型：read / 改写再搜 / 引用结案
  → 评测侧（若有）用合并排名算 IR
```

Agent 场景的固有特点（方案必须承认，不能当 bug 抹掉）：

1. **Query 由模型生成**，会漂移、会缩成单词、会追数字。  
2. **用户语料与 seed 共存**时，字面撞车很常见。  
3. **Claim / 问题措辞 ≠ 文档字面**（语义对、词面弱）是常态，不只出现在学术基准。  
4. 模型在不确定时**倾向再搜**；没有「够用了」信号就会触达多搜。

---

## 2. 流程归因（残余三类）

以下用**流程语言**说明；实现细节见 §4。

| 现象 | 卡在哪一步 | 为什么（产品语义） |
|------|------------|-------------------|
| 语义可召回却 nDCG/可用性崩（例：向量第 5、融合后出 top-K） | **融合 → 截断** | 词面/seed 把「字面像」的文档顶上去，语义金被挤出返回窗口；模型从未看见 |
| 已召回、已阅读，分仍一般 | **融合后的名次** | 金在榜但排在 2–3 名；指标/用户体验都吃「不够靠前」 |
| 已读到高相关仍多次改写搜 | **找到之后的 agent 决策** | 工具结果缺少停止信号；策略鼓励「再确认」；多路合并稀释排名 |

**已修、本文不重复展开**（仍属同一栈）：cover 门因短实体被丢弃、AND keyword 把整单抹空——应保留 ANN / OR 词面；见 runtime `search_sources` 近期改动。

## 3. 成熟目标形态

```text
query
  → 分车道召回
       · work 私有语料（默认主车道）
       · lexical / BM25（可选）
       · seed（可选；空工作区冷启动才默认开）
  → 门控融合或「并集 + 延迟融合」
  → 候选浅重排（只对并集，不对全库）
  → 带 lane / 分差 / 稳定度 的结果给模型
  → 读 / 引 / 必要时再搜（有「够用了」信号与软预算）
  → 结案
```

### 3.1 范围：seed 与私有语料职责分离

| 状态 | Seed | 私有 Work |
|------|------|-----------|
| 空工作区 / 演示 | 默认可检索 | 无或极少 |
| 已有用户/评测物化语料 | **默认不进融合主榜**（可显式 `include_seed`） | 主召回范围 |

理由：seed 是产品冷启动资产，不是每个 Turn 的竞争性语料。私有检索默认 `work_id` 过滤，避免「字面撞上 ATT&CK / 演示文」淹没用户文档——这是**租户与产品边界**，不是评测专用分支。

### 3.2 召回：分车道，截断前保并集

- 各车道独立取 top-N（N 可大于最终展示 K）。  
- **禁止**「先揉成一条榜再一次 top-30」作为唯一路径。  
- 工具结果宜标注命中来自哪条车道（`vector` / `lexical` / `seed`），供模型判别。

### 3.3 融合：门控，而非无条件 RRF

门控示例（产品启发式，需标定，**不是题面特判**）：

- 词面车道仅当存在**强信号**时提高权重：罕见 token / 实体型 token 命中、BM25 头部分值断层大。  
- 词面弱，或与向量榜 **top 重叠过低**（严重分歧）时：**以向量榜为主**，词面仅并列或降权附录。  
- Seed 车道永不单独「否决」私有向量命中；最多并列展示。

目标：语义强、词面弱的文档不被融合步骤挤出返回窗口。

### 3.4 排序：宽召回 + 浅重排

- 并集（例如 50–100）→ 轻量 cross-encoder / 小重排模型 → 再交 top-K。  
- 成本约束：只对本轮候选，不上全库 CE（与既有「热路径 CE」停机纪律相容：此处是**候选集重排**，须单独卡片与成本验收）。  
- Tool 摘要暴露 **相对分差 / 断层**（已有 score_rel 方向可延续），降低盲目再搜。

### 3.5 Agent 环：可停

非硬编码禁搜，而是：

1. **停止建议信号**（写入 tool 结果或短 hint）：  
   - 高分簇相对稳定（改写前后 top 重叠高）；  
   - 已 `read` 的高分文档覆盖查询中的实体型 token；  
   - 本轮改写增益低（新结果与旧结果近乎重复）。  
2. **Scenario / 系统策略**：先读后搜；已有可引用高分来源时优先 `read_file` / 引用。  
3. **软预算**：允许第 2 次检索；第 3 次起提高「说明为何再搜」的成本或降低改写预期（模型仍可搜，不是死封）。

评测桶 `search_cap` 仅作观测；产品对应物是 **diminishing returns 策略**，不是 `n_search` 硬上限写死为唯一手段。

## 4. 与当前栈的缺口映射

| 成熟能力 | 当前大致位置 | 缺口 |
|----------|--------------|------|
| Work 私有为主 | `work_id` 过滤 + 默认 `visibility_seed` | 有语料时 seed 仍常进 ANN/BM25，易污染融合 |
| 分车道可观测 | L2 `lane_*` / audit | 给模型的 hits 多为融合后单列，车道不透明 |
| 门控融合 | hybrid RRF/加权一路到底 | 缺「词面弱则向量优先」 |
| 浅重排 | 基本无（热路径 CE 曾否决） | 候选集重排未产品化 |
| 可停信号 | 弱 / 靠模型自觉 | 缺稳定度、增益、已读覆盖等 hint |
| Cover / keyword 回退 | 已改善（实体 token、OR、保留 ANN） | 保留；勿回退到「cover 失败即清空」 |

结构刀（真 BM25、embed 去噪、doc lane 等）见 `structural-leverage-proposals.md`；与本文正交：**结构刀抬车道质量，本文抬融合与 agent 环纪律**。

## 5. 明确不做（防 hack）

- 按 BEIR 集名 / query id / qrels 分支。  
- 「禁止第三次 `search_sources`」作为唯一方案。  
- 查询路径 LLM 改写 / HyDE 作为主抬分刀（brief R2 红线；与「模型自己改写 query」不同——后者是 agent 自由臂，前者是检索栈代写）。  
- 为评测关掉 hybrid、只开 vector 的隐藏开关（应用显式配置，产品与评测同值对照）。  
- 全库热路径重型 CE 无成本卡（与既有停机纪律一致）。

## 6. 建议落地序（实施时可拆票）

| 序 | 项 | 类型 | 验收（产品语义） |
|----|----|------|------------------|
| A | 私有 Work 默认检索不含 seed（显式 opt-in） | 范围 | 同 query：无 seed 时用户文档名次不被演示语料挤出 top-K；空库冷启动仍可搜 seed |
| B | 分车道并集 + 结果标 lane | 召回/呈现 | audit 与 tool JSON 可见 lane；截断前并集宽度可配 |
| C | 门控融合（词面弱 → 向量优先） | 融合 | 构造「语义近、词面弱」夹具：向量可召回文档不得因弱 BM25+seed 跌出返回窗 |
| D | 候选浅重排（可选卡） | 排序 | 成本上限 + 夹具名次；行为桶不恶化 |
| E | 停止信号 + scenario 软预算 | agent 环 | 多搜率下降；已读高分后仍无限改写的比例下降；IR/任务分不因「禁搜」崩 |

验收温度计：**产品路径 L1 free**（含 SciFact 中库微图等），对照 run_id；禁止只报离线 L0。

---

## 7. 与温度计的关系

- **中库微 L1**（gold+干扰、独立 `*-micro` 图）：适合快速回归「融合是否埋金 / 是否空 hits / 是否无意义多搜」；**不是**全库最终态。  
- **整库 / 多库 L1**：在 A–C 落地且中库稳定后再加档。  
- 任何方案若只在微图涨、在真实私有 Work 跌，视为失败（门禁：产品面与评测同路径）。

---

## 8. 总结

| 问题类型 | 成熟对策落点 |
|----------|----------------|
| 语义金被挤出窗口 | seed 默认隔离 + 分车道并集 + 门控融合 |
| 名次偏弱 | 宽召回 + 候选浅重排 + 分差可见 |
| 找到仍狂搜 | 停止信号 + 先读后搜策略 + 软预算 |

**成熟标准**：同一套配置下，普通用户 Work 与官方 L1 温度计行为一致；优化来自**检索结构与 agent 环信号**，而不是题面或 qrels 硬编码。
